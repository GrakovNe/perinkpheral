Содержание

Часть I. Техническое описание

1. Обзор

perINKpheral - настольный дисплей: чёрно-белая панель E-Ink 4,2" с четырьмя кнопками на базе ESP32-C6. Отображается информация, рассчитанная на чтение с одного взгляда: время, погода, ближайшая встреча, состояние дома.

Прошивка называется хостом. Хост рисует меню и свои уведомления. Все остальные экраны - приложения, в том числе Настройки и О системе: это системные приложения, встроенные в прошивку. Приложения устанавливаются из каталога; прошивка при этом не перезаписывается.

Приложение состоит из модуля WebAssembly и манифеста. Модуль пишется на C с одним заголовочным файлом, sdk/host_api.h, и исполняется интерпретатором (wasm3) внутри хоста.

Собственные страницы хоста, «Настройки» и «О системе», собраны как приложения с тем же заголовочным файлом.

Возможности

  • Дисплей: 400 x 300 пикселей, 1 бит, оттенки серого дизерингом, частичное обновление примерно за 0,5 с
  • Ввод: четыре кнопки; события короткого нажатия, длинного нажатия, нажатия и отпускания
  • Песочница: 64 КБ собственной памяти; доступ в сеть только через хост
  • Сеть: запросы HTTP и HTTPS выполняются хостом - опросы по расписанию или запросы из кода
  • Данные: хост извлекает значения и списки из ответов JSON; любой ответ можно получать потоком кусками по 1 КБ
  • Фоновая работа: ответы, будильники и события устройства доставляются приложению, когда оно не на экране
  • Хранение: хранилище «ключ-значение», сохраняется при перезагрузке и переустановке, и файлы, сохраняются при перезагрузке
  • Дизайн-система: списки, сообщения, выбор значения, ячейки и строка кнопок, отрисовываются хостом
  • Уведомления: показываются хостом поверх любого экрана
  • Настройки: объявляются в манифесте, редактируются на веб-странице устройства
  • Локализация: строки по языкам, загружаются хостом; расширенная латиница, кириллица и греческий
  • Инструменты: сборка, проверка и измерение приложения; управление устройством по сети

Как работает приложение

Приложение - это набор экспортируемых обработчиков с фиксированными именами. Обработчик вызывается хостом при наступлении события: нажатие кнопки, таймер, поступление данных, запрос на отрисовку.

Состояние приложения изменяется в обработчике, после чего запрашивается перерисовка. app_on_draw() вызывается хостом, когда нужен кадр. Момент и способ обновления экрана определяются хостом.

Одновременно загружено одно приложение. Приложение выгружается, когда уходит с экрана. Постоянное состояние хранится в хранилище приложения; глобальные переменные сохраняются до выгрузки.

Гарантии для обработчиков

  • Обработчики выполняются по одному, каждый до завершения. Блокировки не нужны.
  • Обработчик ограничен 3 секундами. Обработчик, превысивший лимит или вызвавший ловушку (например, на неверном указателе), останавливается. Приложение завершается, показывается экран ошибки. Хост продолжает работу.
  • Обработчики возвращают void. Перерисовка, экран или выход получаются запросом. Запросы применяются после возврата из обработчика.
  • app_on_load() вызывается раньше любого другого обработчика экземпляра.
  • События кнопок доставляются по порядку; ждать могут 16, следующее теряется. Ожидающие таймеры с одним номером объединяются. Фрагменты одного ответа доставляются по порядку; между двумя из них может прийти изменение настроек или будильник.
  • Фоновая доставка ответа может прерваться. Нажатие кнопки, смена экрана, перечитывание списка приложений или доставка другому приложению могут выгрузить экземпляр и отбросить оставшиеся части. Вызывается только app_on_terminate(). Опрос повторяется через минуту или через свой интервал, если он короче.

Состояние

Глобальные переменные сохраняются до выгрузки приложения. Оно выгружается при уходе с экрана и по завершении фоновой доставки. При потоковом ответе один экземпляр остаётся загруженным между частями; он также обрабатывает промежуточные события этого приложения.

Состояние загружается в app_on_load() и сохраняется в app_on_terminate() - последнем вызове каждого экземпляра, не остановленного из-за сбоя. Значение, которое должно пережить отключение питания, сохраняется сразу после изменения.

Используйте память сессии для временного состояния интерфейса: текущей страницы, выбранной строки или незавершённого ввода. До 128 байт (HOST_SESSION_MAX) сохраняются при выгрузке, пока приложение остаётся в стеке навигации. Сохраняйте их в app_on_blur(), восстанавливайте в app_on_focus() через app_session_save() и app_session_load(). Сессия очищается при выходе приложения из стека, повторном открытии из меню и перезапуске. Фоновый экземпляр может читать её, но не менять.

Для меток времени, сохраняемых между перезапусками, используйте time_now(). Вместе со временем работы сохраняйте time_boot_id(), чтобы обнаружить предыдущий запуск и отбросить старое значение. Идентификатор запуска - случайное ненулевое 32-битное число; совпадение не гарантирует отсутствия перезапуска.

Сессия подключается после возврата из app_on_load(). Читайте её в app_on_focus() или обработчике фоновой доставки; session_set() в app_on_load() возвращает HOST_ERR_ARGUMENT.

Навигация и обновление экрана

Навигация организована как стек. Внизу находится меню. Приложение, открытое из меню, помещается сверху. Уведомление, вопрос хоста или приложение, запросившее экран, помещается над текущим экраном.

Верхний элемент снимается коротким нажатием BACK. Длинным нажатием BACK стек очищается и открывается меню.

Загружен только верхний элемент. Приложение ниже в стеке выгружено; его состояние восстанавливается при возврате на вершину.

Панелью управляет хост. Каждый новый кадр сравнивается с кадром на панели, передаётся только изменившаяся область. Обновление без нажатия кнопки откладывается, если предыдущее было слишком недавно.

На панели всегда показан целый кадр. Момент обновления определяется хостом.

Часть II. Руководство разработчика

4. Первое приложение

Требования

  • wasi-sdk версии 34 или новее. Содержит clang для цели wasm32. Укажите путь к нему в WASI_SDK_PATH.
  • Java 21 или новее, для tools/perinkpheral: инструменты, собираются при первом запуске. Плагин для CLion несёт те же инструменты, и больше ему ничего не нужно.
  • Копия репозитория perinkpheral. Содержит sdk/ и tools/.
  • Устройство в той же сети с прошивкой, в которой включены инструменты разработки (по умолчанию). Адрес устройства показан на второй странице «О системе». Укажите этот адрес в PERINKPHERAL_HOST.
  • Без устройства: симулятор (раздел 14). Для сборки ему нужен компилятор C; с плагином для CLion он поставляется собранным.

Создание, сборка, запуск

Выполняйте эти команды из корня репозитория.

Создание

tools/perinkpheral new my-app --title "My app"

Запуск на устройстве

tools/perinkpheral run my-app

Запуск в симуляторе

tools/perinkpheral sim my-app

Открытие страницы разработки

tools/perinkpheral serve my-app

run собирает приложение, загружает его, перезапускает устройство и открывает приложение. Это занимает около десяти секунд. Прошивка не перезаписывается.

Сборка считает предупреждения компилятора ошибками (-Wall -Wextra -Werror). Неиспользуемый параметр помечается (void)name;.

serve запускает локальную веб-страницу с экраном устройства, четырьмя кнопками, журналом устройства и кнопкой Run. Клавиши со стрелками, Enter и Backspace работают как кнопки. Страница принимает запросы только от самой себя, как и устройство.

Настройка IDE

new также создаёт CMakeLists.txt в папке приложения. Откройте эту папку в IDE с поддержкой CMake, например CLion или VS Code.

IDE находит заголовочные файлы SDK и сгенерированные strings.h и pictures.h. В проекте четыре цели сборки: my-app (сборка), my-app-package (сборка и проверка пакета, с отчётом), my-app-run (сборка и запуск на устройстве) и my-app-serve (страница с экраном). IDE компилирует с флагами сборки (tools/perinkpheral flags) и получает тот же модуль.

Сгенерированные заголовки создаются при настройке проекта и заново при его перезагрузке после изменения strings/ или pictures/; плагин CLion пересоздаёт их при каждом изменении. Строка, которую код ещё не использует, или перевод, в котором строки не хватает, в них допускаются; сборка отклоняет и то и другое.

Задайте WASI_SDK_PATH и PERINKPHERAL_HOST в окружении CMake в IDE.

Плагин perINKpheral для CLion (репозиторий perinkpheral-clion-plugin) делает эту настройку сам. Он по запросу скачивает SDK и wasi-sdk, открывает папку приложения как проект CMake и добавляет две конфигурации запуска: на устройстве и в симуляторе. Его окно устройства показывает живой экран, кнопки, лог и состояние устройства или симулятора.

Пример приложения

#include "app_text.h"
#include "host_api.h"

#define MARGIN HOST_UI_MARGIN

static const char PRESSES_KEY[] = "presses";
#define PRESSES_KEY_LENGTH ((int32_t)sizeof PRESSES_KEY - 1)

static int32_t presses;

static void draw_line(int32_t line, const char *text)
{
    int32_t line_height = gfx_font_height(HOST_FONT_TEXT);
    gfx_draw_text(MARGIN, MARGIN + line * line_height, HOST_FONT_TEXT, text, app_text_length(text));
}

void app_on_load(void)                 /* загрузить состояние из хранилища */
{
    kv_get(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_terminate(void)         /* сохранить состояние перед выгрузкой */
{
    kv_set(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_button(int32_t event)   /* изменить состояние, запросить перерисовку */
{
    switch (event) {
    case BTN_UP_PRESSED:
    case BTN_OK_PRESSED:
    case BTN_DOWN_PRESSED:
        presses++;
        screen_redraw(HOST_REDRAW_NORMAL);
        break;
    }
}

void app_on_draw(void)              /* нарисовать весь кадр по состоянию */
{
    char       counter_buffer[32];
    app_text_t counter;
    app_text_start(&counter, counter_buffer, sizeof counter_buffer);
    app_text_add(&counter, "Presses: ");
    app_text_add_number(&counter, presses);

    draw_line(0, "Hello from wasm");
    draw_line(2, counter_buffer);
}

BACK здесь обрабатывается хостом: короткое нажатие BACK закрывает приложение, у которого нет экспорта app_on_back().

Журнал сообщает о двух состояниях работающего приложения, один раз на экземпляр или в минуту: обработчик выполняется дольше 400 мс (slow handler: on_draw took 520 ms), и более 12 записей в хранилище за минуту. Каждая запись в хранилище - запись во флеш: состояние сохраняется в app_on_terminate().

Сборка также завершается ошибкой в следующих случаях:

  • модуль импортирует функцию, не объявленную в host_api.h;
  • код содержит операцию с плавающей точкой (отчёт её называет);
  • код вызывает функцию sys_*, а в манифесте нет "system": true;
  • код вызывает file_write(), а в манифесте нет "writes_files": true;
  • манифест превышает лимит;
  • перевод не соответствует en.json (раздел 12);
  • функция названа как обработчик (app_on_...), а такого обработчика у хоста нет;
  • код вызывает timer_set(), alarm_set*() или http_send() и не содержит обработчика, который получает результат;
  • манифест объявляет опрос или интенты, а в коде нет app_on_picked(), app_on_data() или app_on_intent();
  • код рисует и не содержит app_on_draw();
  • строка из strings/ или картинка из pictures/ не используется в коде.

Подстановки настроек

{{key}} читает KV-хранилище приложения, включая необъявленные ключи; отсутствующая объявленная настройка берётся из значения по умолчанию в манифесте. Значение подставляется с процентным кодированием: каждый символ, кроме букв, цифр и - . _ ~, становится %XX, включая /. Одна настройка - один сегмент пути: для owner/name нужны два ключа, /repos/{{owner}}/{{name}}. Начальная настройка url и настройка link вставляются без изменений. Настройка list вставляется поэлементно с кодированием и запятыми между элементами: symbols={{tickers}} превращается в symbols=AAPL,MSFT. Пустая настройка в URL или заголовке опроса даёт HOST_FAILED_NOT_READY; поэтому токен в заголовке обязателен.

https://api.example.com/repos/{{owner}}/{{name}}
{{server}}/api/status
{{calendar}}
https://api.example.com/quote?symbols={{tickers}}

Опросы нумеруются с 0 в порядке списка. Этот номер получают обработчики.

"settings": [ { "key": "tickers", "type": "list", "title": "Tickers", "default": ["AAPL", "MSFT"] } ],
"polls": [ { "url": "https://api.example.com/chart/{{tickers}}", "every": 900,
             "each": "tickers", "pick": ["quote.name", "quote.closes[*]"] } ]

response:  { "quote": { "name": "Apple Inc.", "closes": [356.11, 356.40, null, 356.27] } }

Путь отсчитывается от начала ответа: [0] и [*] могут быть в одном пути, chart.result[0].closes[*]. При пустом списке хост пытается выполнить один опрос с answer_item(), равным -1. Он завершается с HOST_FAILED_NOT_READY, если подстановка требует пустое значение списка; фиксированный URL без ссылки на список может быть запрошен.

Настройки

Настройки объявляются в манифесте. Веб-страница устройства строит форму настроек только по манифесту. Каждое значение хранится как текст в хранилище приложения под ключом настройки.

Приложение читает настройку вызовом kv_get() по ключу настройки.

Значения формы настроек должны быть печатным ASCII; для списков также разрешён перевод строки между элементами.

Когда пользователь сохраняет форму, хост вызывает app_on_settings() и сразу повторяет все опросы.

  • Настройки типов url и link доступны приложению только для чтения: kv_set() по их ключам завершается ошибкой. Когда пользователь меняет такую настройку, хост стирает секреты, не введённые заново, поэтому токен остаётся с тем сервером, для которого был введён.
  • title - от 1 до 31 символа. help - до 95 символов.

Хост проверяет переданные настройки перед записью, но запись не является транзакцией. Ошибка хранилища может оставить часть значений изменёнными. Если хотя бы одна запись успешна, вызывается app_on_settings() и снова запрашиваются опросы, даже при частичной ошибке сохранения.

Страница companion

Разместите статическую HTTPS-страницу и укажите её URL в companion. Страница устройства открывает её в отдельном окне для настройки, которую обычная форма не позволяет выполнить. См. sdk/companion/example.html.

{ perinkpheral: "ready" }
{ perinkpheral: "app", name, title, settings, values }
{ perinkpheral: "settings", values: { key: "value" } }

Страница companion посылает ready; страница устройства отвечает сообщением app с настройками манифеста и их текущими значениями. Значения secret и link не передаются. Страница companion возвращает settings с объявленными ключами и строковыми значениями до 255 байт. Они заполняют форму; для сохранения пользователь должен нажать «Сохранить».

Проверяйте event.source на равенство window.opener, а event.origin - на ожидаемый источник страницы устройства. Используйте этот источник как цель postMessage при отправке значений. Первое сообщение ready не содержит данных пользователя.

6. Экран

Поверхность и цвет

  • Начало координат - левый верхний угол поверхности. gfx_width() и gfx_height() возвращают её размер. Используйте эти значения для компоновки.
  • Вызовы отрисовки работают внутри app_on_draw(). В начале каждого вызова поверхность белая. В любом другом обработчике вызовы отрисовки gfx_* и ui_* возвращают HOST_ERR_NOT_DRAWING; измерение текста и шрифтов работает везде. Отрисовка обрезается по границам поверхности.
  • gfx_set_color() задаёт цвет для последующих вызовов, от HOST_PAPER (0) до HOST_INK (16). В начале каждого app_on_draw() цвет равен HOST_INK. Промежуточные значения - оттенки серого, получаемые дизерингом. Используйте серый только для заливок: тонкие линии и мелкий текст становятся нечитаемыми.
  • Стандартное поле - HOST_UI_MARGIN (16 пикселей). Используйте его у левого и правого краёв.

Шрифты

Константа шрифта задаёт размер. Гарнитура - настройка пользователя: Departure Mono (моноширинная) или Jersey (пропорциональная). Ширина символов у них разная, поэтому компоновка строится на измеренной ширине.

Измеряйте текст вызовами gfx_text_width(), gfx_font_height(), gfx_font_ascent() и gfx_font_cap_height().

Текст за пределами ASCII

Отображаемый текст - UTF-8. Для каждого символа хост использует первый доступный вариант:

  1. Глиф символа. Печатные символы ASCII доступны всегда. Расширенная латиница, кириллица и греческий доступны, если пользователь установил пакет глифов («Настройки», «Язык» на веб-странице устройства).
  2. Транслитерация в ASCII: "Moskva", "Strasse", "Athina". Типографские тире и кавычки заменяются простыми.
  3. Вопросительный знак.

Знак градуса встроен во все размеры.

Ширина текста зависит от использованного способа. Всегда измеряйте текст перед размещением.

Текст манифеста для пользователя ограничен и числом символов, и числом байт UTF-8, равным удвоенному лимиту символов. Название содержит до 23 символов и 46 байт. Поле контракта, например строка уведомления, имеет размер в байтах и вмещает вдвое меньше двухбайтовых символов, чем однобайтовых.

Картинка хранится по одному биту на клетку. gfx_draw_picture() рисует её с размером клетки от 1 до 16 пикселей, поэтому одну картинку можно использовать в нескольких размерах.

Картинку, слишком большую для модуля, размещайте в files/ и рисуйте вызовом gfx_draw_bitmap_file(). Хост читает файл напрямую; память приложения картинка не занимает.

7. Кнопки

Кнопки по порядку: UP, OK, DOWN, BACK. Хост использует их одинаково на всех экранах. Приложениям следует сохранять эти значения.

Каждое нажатие порождает события двух видов. Низкоуровневые события - KEYDOWN и KEYUP. Интерпретированные события - PRESSED, отправляется по окончании короткого нажатия, и LONG_PRESSED, отправляется через 600 мс, пока кнопка ещё удерживается. Длинное нажатие не порождает PRESSED.

Большинство приложений обрабатывает только PRESSED и LONG_PRESSED.

Значение события объединяет кнопку и действие. У каждой комбинации есть константа:

void app_on_button(int32_t event)
{
    switch (event) {
    case BTN_OK_PRESSED:       start();  break;
    case BTN_OK_LONG_PRESSED:  reset();  break;
    }
    screen_redraw(HOST_REDRAW_NORMAL);
}

8. Хранение

Хранилище

kv_get() и kv_set() читают и записывают небольшие значения по ключу. У каждого приложения собственное пространство имён.

Хранилище содержит состояние приложения и настройки. При удалении оно обычно сохраняется для повторной установки. При заполнении раздела хост может стереть данные удалённых приложений. Удаление с «забыть» стирает их сразу.

typedef struct { int32_t version; int32_t minutes; int64_t ends_at; } state_t;
static state_t state;

void app_on_load(void)
{
    if (kv_get("state", 5, &state, sizeof state) != sizeof state || state.version != 2) {
        state = (state_t){ .version = 2, .minutes = 25 };     /* нет сохранённого состояния или старая версия */
    }
}
  • Добавляйте поле версии в каждую сохраняемую структуру и проверяйте его при загрузке. Новая версия приложения будет читать данные, записанные старой.
  • Каждая запись изнашивает флеш-память. Записывайте, только когда данные изменились. Не записывайте по каждому срабатыванию таймера.
  • kv_set() с длиной 0 удаляет ключ.

Файлы

Используйте файлы для данных, не помещающихся в значение хранилища: загруженный список, кэш, картинка.

file_read() и file_write() принимают смещение. Файл можно читать и дописывать частями, поэтому держать его в памяти целиком не требуется.

Файлы из папки files/ пакета устанавливаются вместе с приложением.

  • Существующие файлы остаются, если обновление не содержит файла с тем же именем: такой файл заменяется. Для записываемых кешей используйте имена, которых нет в пакете. При удалении приложения файлы удаляются.
  • Запись начинается внутри файла или в его конце. Чтобы заменить файл более коротким, сначала удалите его: file_write() с длиной 0 по смещению 0.
  • Для записи нужно "writes_files": true в манифесте. Общий лимит - 32 KB, включая файлы данных пакета. Неиспользованная часть резервируется за приложением. При установке из каталога в этот лимит входит и манифест.
  • Каждый файл занимает целые блоки по 4 КБ из 32 КБ. Храните связанные записи в одном файле.

9. Сеть

Весь доступ к сети идёт через хост. Приложение описывает запрос; хост выполняет его и доставляет ответ. На всём устройстве одновременно выполняется один запрос. Ответы обычно доставляются и на экране, и вне его. Отказ в опросе до начала запроса из-за отсутствия сети или памяти сессии сообщается только приложению на экране.

О доступности сети сообщает ответ: запрос, сделанный без сети, завершается ошибкой HOST_FAILED_NO_NETWORK.

Значения, извлечённые хостом

#include "app_values.h"
enum { VALUE_TEMPERATURE, VALUE_CODE };            /* порядок "pick" в манифесте */

void app_on_picked(int32_t request, int32_t http_status)
{
    int32_t tenths, code;
    last_status = http_status;                     /* для ui_draw_reason(), когда данных нет */
    if (http_status == 200 &&
        app_value_number(VALUE_TEMPERATURE, 1, &tenths) &&      /* "21.46" -> 215 */
        app_value_number(VALUE_CODE, 0, &code)) {
        keep(tenths, code);                        /* сохранить в хранилище */
    }                                              /* иначе оставить прежние данные */
    screen_redraw(HOST_REDRAW_NORMAL);
}

Числа - целые. app_value_number() возвращает значение, умноженное на 10^decimals и округлённое до целого.

У пути, отсутствующего в ответе, нет значения: app_value_number() возвращает false. Отсутствующее значение означает отсутствие данных.

Списки

Путь с [*] вместо одного индекса - путь списка: все элементы этого массива по порядку. app_value_count() возвращает число элементов. app_value_series() превращает их в числа для ui_draw_chart():

/* "pick": ["quote.name", "quote.closes[*]"] */
static int32_t prices[HOST_CHART_VALUES_MAX];
static int32_t count;

void app_on_picked(int32_t request, int32_t http_status)
{
    int32_t item = answer_item();                                    /* какой тикер из списка */
    if (http_status == 200) {
        count = app_value_series(1, 2, prices, HOST_CHART_VALUES_MAX);  /* сотые; "null" - пропуск */
    }
}
  • Элемент null сохраняется как пропуск в ряду, чтобы два списка одного массива шли в ногу. Элемент без остатка пути (items[*].title у пункта без title) пропускается.
  • Элементы одного ответа занимают до 8 КБ текстом (HOST_LIST_BYTES); каждый занимает число байт, равное его длине плюс 2. Элементы сверх этого отбрасываются, и об этом сообщается в журнале.
  • Если элементов больше, чем места, app_value_series() берёт равномерно распределённые элементы, включая первый и последний.
  • Значение достаётся первому пути, который его называет: a[*] перед a[0] забирает элемент.

Числа

Плавающей точки нет. Число - целое с фиксированным числом знаков после запятой: 356.27 - это 35627 с 2 знаками. app_fixed.h читает, переводит и записывает такие числа в 64 битах:

int64_t price, previous;
app_value_fixed(VALUE_PRICE, 2, &price);                       /* "356.2699890136719" -> 35627 */
app_value_fixed(VALUE_PREVIOUS, 2, &previous);
int64_t percent = app_fixed_ratio((price - previous) * 100, previous, 2);  /* -> 39: +0.39 % */
app_text_add_fixed(&text, price - previous, 2, APP_FIXED_SIGN);        /* "+1.39" */

Потоковые ответы

void app_on_data(int32_t request, const uint8_t *data, int32_t length, int32_t flags, int32_t http_status)
{
    if (flags & HOST_DATA_FAILED) {                /* ошибка без данных; отбросить все предыдущие фрагменты: http_status содержит код HOST_FAILED_* */
        last_status = http_status;
        return;
    }
    if (flags & HOST_DATA_FIRST) {                 /* с первым фрагментом приходит статус HTTP */
        last_status = http_status;
        begin_reading();                           /* сбросить разборщик */
    }
    read_piece(data, length);                      /* данные действительны до возврата из обработчика */
    if (flags & HOST_DATA_LAST) {
        take_what_was_read();                      /* ответ получен целиком */
        screen_redraw(HOST_REDRAW_NORMAL);
    }
}
  • Обрабатывайте каждый кусок по приходу и храните только данные для показа. Используйте конечный автомат, json_pick из SDK или свой разборщик. Ответ может занимать несколько мегабайт; у приложения 64 КБ. json_pick принимает и пути списков, с буфером, который даёт приложение (раздел 23).
  • Заменяйте отображаемые данные только по HOST_DATA_LAST. Доставка может прекратиться без последнего фрагмента и без ошибки (раздел 3). HOST_DATA_FIRST всегда начинает новый ответ.
  • В обработчике answer_info(&response, sizeof response) копирует метаданные ответа и возвращает число записанных байт: status, Content-Length, Content-Type, ETag, Last-Modified, Location, Link и Retry-After. Копируется не больше размера структуры хоста; отсутствующие поля обнулены, кроме length, равного -1 при отсутствии длины.

Успешные части ответа имеют общие метаданные. Завершающий вызов с HOST_DATA_FAILED может не иметь метаданных: answer_info() возвращает код ошибки как status, length -1 и пустые строки заголовков. Неверный или незавершённый JSON с извлечением значений даёт HOST_FAILED_NO_ANSWER, даже если HTTP-ответ получен.

Запросы из кода

enum { REQUEST_TOGGLE = HOST_REQUEST_FIRST };
static const char URL[]     = "{{server}}/api/services/light/toggle";
static const char HEADERS[] = "Authorization: Bearer {{token}}\nContent-Type: application/json";

http_send(REQUEST_TOGGLE, HOST_HTTP_POST, URL, sizeof URL - 1, HEADERS, sizeof HEADERS - 1,
             body, body_length);
  • Запросы разрешены только на адреса, перечисленные в манифесте. Подстановки {{key}} работают в URL и в значениях заголовков, поэтому коду не нужно читать токен.
  • У приложения может ждать 16 запросов (HOST_HTTP_PENDING_MAX). Если нужно больше, ставьте следующие по мере прихода ответов; в конце концов выполняется каждый запрос. Приложения чередуются, и опросы чередуются с запросами. HOST_ERR_NO_SPACE означает, что ждут 16 или что у устройства нет памяти ещё на один.
  • Хост отправляет User-Agent: perinkpheral. Заголовок User-Agent от приложения заменяет его, в опросе и в запросе.
  • Прерванный ответ на запрос из кода (раздел 3) отбрасывается: запрос не повторяется. Если ответ ещё нужен, запросите снова из app_on_terminate() или позже.
  • Для GET хост выполняет до трёх перенаправлений. Перенаправление на адрес вне списка завершается ошибкой HOST_FAILED_NOT_ALLOWED. Запрос другим методом отправляется один раз; ответ с перенаправлением доставляется как ответ на запрос.
  • poll_run(n) запрашивает опрос n через общую очередь без ожидания ответа; повторные ожидающие запросы объединяются, например при нажатии кнопки обновления. poll_set_interval(n, seconds) меняет интервал опроса из кода, например по заголовку Retry-After.

Для http_send() URL подставляется и впервые проверяется до постановки в очередь. Неустановленное значение URL даёт HOST_ERR_ARGUMENT без обработчика ответа. В очереди остаётся раскрытый адрес. Перед отправкой адрес проверяется заново, а заголовки заполняются из того же текущего снимка KV. Если изменение настроек запретило прежний адрес, приходит HOST_FAILED_NOT_ALLOWED; запрос никогда молча не перенаправляется на новый сервер. Отсутствующие или недопустимые значения заголовков дают HOST_FAILED_NOT_READY. Подготовленный запрос сохраняет свой снимок при передаче. URL вмещает 511 байт, значение заголовка - 255 байт; тело копируется при постановке в очередь.

Лимит 16 ожидающих запросов задан на приложение без резервирования мест. Все запросы делят 16 KB на записи очереди, URL, заголовки и тела. HOST_ERR_NO_SPACE возможен и при меньшем числе запросов. Имя исходного заголовка - до 31 байта, значение - до 255 байт.

Центры сертификации приложения

Хост проверяет HTTPS-серверы по набору корневых сертификатов браузеров. Запрос к серверу, сертификат которого выдан центром сертификации вне этого набора, завершается с HOST_FAILED_NOT_TRUSTED. Приложение, которому нужен такой сервер, приносит корневой сертификат этого центра в своём пакете и называет его в манифесте:

"certificates": ["russian-root-ca.pem"]          /* files/russian-root-ca.pem */
  • Каждый файл - корневой сертификат центра сертификации в PEM или DER, до 4 КБ. Сборка отклоняет файл, которого нет, который не является сертификатом, является сертификатом сервера или просрочен.
  • Этим корневым сертификатам доверяют только опросы и запросы этого приложения, в дополнение к набору браузеров. Другие приложения и хост им не доверяют.
  • Веб-страница называет эти центры перед установкой, как и системный доступ, и в карточке приложения. Индекс каталога содержит их имена.
  • Берите корневой сертификат из публикации самого центра сертификации и сверяйте его отпечаток с тем, что предъявляет сервер.

11. Время

  • time_now() возвращает время Unix в секундах. Возвращает 0, пока устройство не получило время. Приложение обязано обрабатывать этот случай.
  • Отображайте местное время. Часовым поясом управляет хост. time_local() возвращает текущие местные дату и время, time_local_at() преобразует любой момент, time_from_local() преобразует местные дату и время обратно во время Unix, например для alarm_set_at().
  • time_text() форматирует момент времени как текст на языке устройства. Собственные названия дней и месяцев приложениям не нужны. Форматы: "15:04", "Пт 13 ноя", "Пятница", "Пт", "13 ноября" и относительная форма: "15:04", "Завтра 15:04", "Сб 15:04", "21 ноя".
  • Чтобы получать вызов при установке или изменении часов, объявите интент time_changed.

Ключи строк приложения соответствуют [a-z][a-z0-9_]*. Сгенерированные константы начинаются с STR_, затем идёт ключ в верхнем регистре.

Приложение отображает свой текст на языке устройства. Переводы предоставляет разработчик. Хост загружает перевод для текущего языка.

  • При загрузке приложения хост копирует таблицу строк на языке устройства в память приложения поверх английской. После этого app_string() возвращает переведённый текст без дополнительного вызова.

  • Перевод может быть длиннее или короче оригинала. Проверяйте каждый поддерживаемый язык с обеими гарнитурами, включая длинные подписи и усечённый текст.

13. Правила проектирования

Эти правила относятся ко всем приложениям. Экраны самого хоста им следуют. Большинство из них - соглашения; хост проверяет лишь некоторые.

Содержимое экрана

Показывайте одно главное значение на экране. Устройство читают примерно с метра, примерно за секунду. Выберите главное значение, нарисуйте его самым крупным, остальное оставьте мелким.
Делайте экраны статичными. Меняйте экран, только когда меняются его данные. Полоса показывает количество. Для индикации работы показывайте сообщение с is_working.
Перерисовывайте только при изменении содержимого. Таймер должен запрашивать перерисовку, только если изображение изменится. Часы перерисовываются раз в минуту, на границе минуты. По умолчанию хост допускает одно обновление в минуту без нажатия кнопки. Проектируйте под эту частоту.
Рисуйте чёрным по белому. Используйте чернила на бумаге. Серый используйте только для заливок. Белый текст на чёрной полосе используйте только для выбранного элемента или новой информации.
Делайте текст интерфейса коротким и стандартным. Используйте общепринятые слова: «Сохранить», «Удалить», «Настройте». Если подпись требует пояснения, смените подпись.

Память

Сокращайте сначала размер кода, затем размер данных. Каждый байт исполненного кода занимает около четырёх байт из 64 КБ интерпретатора. Каждый байт данных занимает один байт страницы 64 КБ, которая в основном свободна. Предпочитайте таблицу цепочке операторов if, Kit - собственной отрисовке, pick - собственному разборщику, time_text() - собственному форматированию дат.
Не встраивайте общие вспомогательные функции. Небольшую вспомогательную функцию, вызываемую из многих мест, помечайте __attribute__((noinline)) и сравнивайте отчёты сборки.
Храните картинки в битах. Размещайте картинки в pictures/. Большие картинки размещайте в files/.
Обрабатывайте ответы потоком. Обрабатывайте ответ по мере поступления и оставляйте только данные для отображения. Перед выделением временных буферов через app_alloc() вызывайте app_alloc_mark(). По завершении вызывайте app_alloc_release(mark), освобождая всё, что выделено после отметки (раздел 23).

Состояние и время

Сохраняйте состояние перед каждой выгрузкой. Постоянные данные храните в хранилище. Навигацию и незавершённый ввод сохраняйте в сессии в app_on_blur(); восстанавливайте в app_on_focus(). Открытие из меню начинает новую сессию.
Сохраняйте показанные данные, пока новые не получены целиком. После неудавшегося или прерванного запроса оставляйте на экране прежние данные.
Объясняйте пустой экран. Вызывайте ui_draw_reason(), чтобы показать "Настройте", "Нет сети" или "Загрузка".
Обрабатывайте неизвестное или изменённое время. Обрабатывайте time_now() == 0. Используйте alarm_set() для задержки («через десять минут») и alarm_set_at() для времени по часам («в семь»).

Взаимодействие и данные

Принимайте текстовый ввод на веб-странице. Текст - токен, адрес, город - объявляйте настройкой в манифесте; пользователь вводит его на веб-странице устройства. На устройстве давайте пользователю выбор из нескольких значений кнопками UP и DOWN.
Занимайте экран редко. Используйте уведомление только для событий, о которых пользователь просил сообщать, например таймер или встреча. Остальная информация ждёт, пока пользователь посмотрит на устройство.
Отправляйте данные пользователя только туда, куда он указал. Перечисляйте только те адреса, которые нужны приложению. Для собственного сервера пользователя используйте настройку типа url. Для токена используйте настройку типа secret и передавайте его подстановкой в заголовке.
Опрашивайте не чаще, чем меняются данные. Предлагайте интервал как настройку с разумным значением по умолчанию. При питании от батареи хост ограничивает каждый опрос одним разом в пять минут.

15. Публикация

Устройство устанавливает приложения из каталогов. Каталог - папка статических файлов с индексом. Его можно разместить на любом хостинге с HTTPS, например в виде файлов git-репозитория или статического сайта.

tools/perinkpheral catalog my-apps --out catalog       # собрать все приложения в папке
                                                       # результат: catalog/catalog.json и по папке на приложение
  • Выходная папка создаётся заново при каждом запуске. Она должна быть пустой или прежним каталогом и не должна содержать сами приложения.
  • В индексе перечислены имя, название, версия и иконка каждого приложения, а также его файлы с размерами и хешами SHA-256. Устройство принимает файл, только если совпадают и размер, и хеш.
  • Модель доверия: HTTPS до источника, выбранного пользователем, плюс песочница. Пакеты не подписываются.
  • Официальный каталог - репозиторий perinkpheral-apps. Это первый источник на каждом устройстве. Пользователь может добавить ещё до трёх источников на веб-странице устройства, указав адрес репозитория.
  • Веб-страница показывает сводку по каждому установленному приложению, взятую из манифеста: серверы, к которым оно подключается, интервал опроса, что оно хранит и запускается ли вместе с устройством.
  • Увеличивайте version при каждом изменении. Устройство сравнивает версии, чтобы обнаружить обновления.

Часть III. Справочник

Этот раздел кратко описывает вызовы хоста и экспорты для ABI 3. Сигнатуры сокращены. Подключайте sdk/host_api.h; полные типы, константы и объявления находятся в sdk/host/*.h.

sdk/host_api.h - основной контракт. Если этот документ и заголовочный файл расходятся, верен заголовочный файл.

Вызовы хоста возвращают ошибки HOST_ERR_* напрямую. Сетевые ошибки приходят позже в обработчик данных как статусы HOST_FAILED_*; см. «Ошибки запросов» в разделе 9.

Числовые аргументы и возвращаемые значения имеют тип int32_t, если не указано иное. Текстовый аргумент - указатель и длина в байтах; текст в UTF-8.

Вызов без собственного возвращаемого значения возвращает HOST_OK или отрицательный код HOST_ERR_*.

Команды называют предмет, затем действие (kv_get, gfx_draw_text); запросы называют предмет и то, что требуется узнать (gfx_width, time_now); события, вызываемые хостом, используют app_on_<what happened> (app_on_load, app_on_picked).

Совместимость ABI 3

ABI 3 готовится к первому выпуску с зафиксированным контрактом. После выпуска существующие имена, типы wasm, привилегии, константы, раскладки и смысл вызовов сохраняются в следующих прошивках. Изменение сигнатуры или смысла требует нового ABI; HOST_SINCE_ отмечает только элементы, добавленные после нижней границы ABI 3, версии 0.1.30. Выпуски прошивки и поколения ABI независимы. Отсутствующие экспорты остаются необязательными.

Поддерживается множество {3}. ABI манифеста передаётся до загрузки и проверяется до выполнения кода. Страница устройства вместе проверяет принадлежность ABI и минимум прошивки для Install, Update и Update all; /api/status сообщает supported_abis. Окончательное решение принимается по загруженному манифесту. При публикации каталога данные об идентичности и совместимости берутся из упакованного манифеста.

tools/perinkpheral contract snapshot записывает контракт в sdk/abi/3.txt, а хеши пакетов отдельно в sdk/abi/3/fixtures.txt; contract check проверяет оба файла в тестах хоста и CI. Записанные элементы нельзя менять или удалять; дополнения разрешены. Запись снимка тоже отклоняет изменения. Зафиксированные пакеты в sdk/abi/3/ служат входными данными тестов, которые никогда их не пересобирают: Probe, Hello, Settings с переводами и состояние Hello (presses = 42 в четырёх байтах little-endian). Нижняя граница ABI 3 - 0.1.30, первая прошивка с ABI 3.

Бинарное представление и буферы

Контракт использует раскладку C для wasm32 little-endian и дополнительный код для знаковых целых. Указатель - беззнаковое 32-битное смещение в памяти; ноль означает NULL. Размер и выравнивание 32-битных целых и указателей равны 4, 64-битных целых - 8, байтов - 1. Структуры сохраняют порядок полей C, естественное выравнивание и конечное заполнение. sdk/abi/3.txt записывает каждый размер, выравнивание, тип и смещение поля. Размер, число строк и смещения таблицы строк - 16-битные слова little-endian. Размеры картинок задаются байтами; строки битовой карты идут старшим битом вперёд и дополняются до целого числа байтов.

Входные буферы используются или копируются до возврата импорта. Хост сохраняет только хранилища экспортов app_data_buffer и app_strings_buffer на время жизни загруженного экземпляра; они должны быть доступны до выгрузки. Данные обработчика действительны до его возврата. Длины и ёмкости считаются в байтах. К текстовому результату не добавляется NUL, кроме строковых полей фиксированного host_answer_info_t. Отрицательные длины и ёмкости и недопустимые диапазоны памяти дают HOST_ERR_ARGUMENT.

kv_get, answer_value, answer_element, session_get, sys_info, sys_app_title и sys_setting_get возвращают HOST_ERR_NO_SPACE, ничего не копируя, если значение не помещается. Нулевая ёмкость допустима для пустого значения. gfx_fit_text также требует места для всего подогнанного результата и ничего не копирует при ошибке. text_fill и time_text вместо этого обрезают между символами UTF-8 и возвращают число скопированных байтов; text_fill принимает нулевую ёмкость, time_text отказывает. Ошибки чтения, форматирования и измерения оставляют выходы неизменными; file_read может скопировать начало до ошибки хранилища. answer_info копирует min(capacity, размер структуры хоста), принимает ноль и не трогает последующие байты. sys_app_list записывает не более capacity идентификаторов, но возвращает общее число; нулевая ёмкость допустима.

Уведомления об установке и обновлении считаются доставленными после загрузки и до обработчика, в том числе при отсутствии обработчика или trap в app_on_load либо обработчике. Ошибка загрузки оставляет уведомление до запуска устройства или перечитывания списка приложений. Обновление означает другой идентификатор пакета из модуля и манифеста, независимо от порядка строк версий.

Только HOST_DATA_LAST делает потоковый ответ полным. HOST_DATA_FAILED может прийти после предыдущих фрагментов и отменяет их все. Прерванный ответ может закончиться без обоих флагов. Границы фрагментов не определены, даже внутри символа UTF-8 или маркера документа. Сохраняйте предыдущий показанный результат до LAST.

Отрисовка сохраняет существующие правила: совместные флаги перерисовки выбирают CLEAN раньше NO_BLINK, затем SOON; QUESTION независим. При отключённом дизеринге оттенки gfx_set_color 1..7 становятся бумагой, 8..15 - чернилами. Первые и последние координаты чернил иконки включительны; end_x текста исключителен.

Системные настройки открывают только явно перечисленные видимые на странице ключи sdk/host/sys.h, где для каждого указаны тип, единицы, включительные диапазоны, специальные значения и необходимость перезапуска. Неизвестные и внутренние ключи, включая refresh_min_button_ms, возвращают HOST_ERR_NOT_FOUND для get, set и range. SSID Wi-Fi здесь доступен только для чтения; пароль нельзя ни читать, ни писать (HOST_ERR_ARGUMENT). Сеть изменяют через страницу или SYS_DO_FORGET_NETWORK.

22. Системный API

Системный API - набор вызовов sys_*. Его используют собственные страницы хоста.

Системный API доступен любому приложению, в манифесте которого есть "system": true. Перед установкой такого приложения веб-страница предупреждает пользователя. Модуль, импортирующий вызов sys_* без этого объявления, отклоняется.

strings.h и pictures.h генерируются для каждого приложения. Сборка ставит их первыми в пути поиска заголовочных файлов, поэтому системный заголовочный файл с тем же именем не используется.

memcpy, memmove, memset и strlen предоставляются, потому что компилятор генерирует их вызовы. Это вся библиотека C платформы. Они не объявлены ни в одном заголовке SDK: код, который вызывает их напрямую, объявляет прототип сам. app_text_length() из app_text.h заменяет strlen.
