1. Overview
1. Обзор

perINKpheral is a desk display: a 4.2" black-and-white e-paper panel with four buttons, built on an ESP32-C6. Information intended for reading at a glance is displayed: time, weather, the next meeting, the state of a home.
perINKpheral - настольный дисплей: чёрно-белая панель E-Ink 4,2" с четырьмя кнопками на базе ESP32-C6. Отображается информация, рассчитанная на чтение с одного взгляда: время, погода, ближайшая встреча, состояние дома.

<i>Perinkpheral OS</i> is a specialized operating system for e-paper, built on FreeRTOS/ESP-IDF. It draws the menu and its own notices. Its other screens are <i>applications</i>, Settings and About among them: they are system applications, carried in the firmware. Applications are installed from a catalog; the firmware is not reflashed.
<i>Perinkpheral OS</i> — специализированная ОС для e-paper на базе FreeRTOS/ESP-IDF. Она рисует меню и свои сообщения. Остальные её экраны - <i>приложения</i>, в том числе Настройки и О системе: это системные приложения, встроенные в прошивку. Приложения устанавливаются из каталога, без перепрошивки устройства.

An independent recovery image installs firmware updates and runs no applications. Ordinary OTA replaces only the main firmware and preserves installed packages and their data.
Отдельная прошивка восстановления устанавливает обновления и не запускает приложения. Обычное OTA заменяет только основную прошивку, сохраняя установленные пакеты и их данные.

An application consists of a WebAssembly module and a manifest. The module is written in C against a single header, <code>sdk/host_api.h</code>, and is executed by an interpreter (wasm3) inside Perinkpheral OS.
Приложение состоит из модуля WebAssembly и манифеста. Модуль пишется на C с одним заголовочным файлом, <code>sdk/host_api.h</code>, и исполняется интерпретатором (wasm3) внутри Perinkpheral OS.

Perinkpheral OS's own pages, Settings and About, are built as applications with the same header.
Собственные страницы Perinkpheral OS, «Настройки» и «О системе», собраны как приложения с тем же заголовочным файлом.

Design system: lists, notices, pickers, cells and a button row, drawn by Perinkpheral OS

How an application runs
Как работает приложение

An application is a set of exported handlers with fixed names. A handler is called by Perinkpheral OS when an event occurs: a button press, a timer, incoming data, a request to draw.
Приложение - это набор экспортируемых обработчиков с фиксированными именами. Обработчик вызывается Perinkpheral OS при наступлении события: нажатие кнопки, таймер, поступление данных, запрос на отрисовку.

The application's state is updated in a handler, and a redraw is requested. <code>app_on_draw()</code> is called by Perinkpheral OS when a frame is needed. Refresh timing and method are decided by Perinkpheral OS.
Состояние приложения изменяется в обработчике, после чего запрашивается перерисовка. <code>app_on_draw()</code> вызывается Perinkpheral OS, когда нужен кадр. Момент и способ обновления экрана определяются Perinkpheral OS.

One application is loaded at a time. An application is unloaded when it leaves the screen. Persistent state is kept in the application's store; global variables are kept until the unload.
Одновременно загружено одно приложение. Приложение выгружается, когда уходит с экрана. Постоянное состояние хранится в хранилище приложения; глобальные переменные сохраняются до выгрузки.

Handler guarantees
Гарантии для обработчиков

Handlers are run one at a time, each to completion. Locking is unnecessary.
Обработчики выполняются по одному, каждый до завершения. Блокировки не нужны.

A handler is limited to 3 seconds. A handler that exceeds the limit, or traps (for example, on an invalid pointer), is stopped. The application is then terminated and an error screen is shown. Perinkpheral OS is unaffected.
Обработчик ограничен 3 секундами. Обработчик, превысивший лимит или вызвавший ловушку (например, на неверном указателе), останавливается. Приложение завершается, показывается экран ошибки. Perinkpheral OS продолжает работу.

Handlers return <code>void</code>. A redraw, the screen or an exit is obtained with a request. Requests are applied after the handler returns.
Обработчики возвращают <code>void</code>. Перерисовка, экран или выход получаются запросом. Запросы применяются после возврата из обработчика.

<code>app_on_load()</code> is called before any other handler of an instance.
<code>app_on_load()</code> вызывается раньше любого другого обработчика экземпляра.

Button events are delivered in order; 16 can wait, and one more is lost. Pending timers with the same number are merged. The pieces of one response are delivered in order; a settings change or an alarm may be delivered between two of them.
События кнопок доставляются по порядку; ждать могут 16, следующее теряется. Ожидающие таймеры с одним номером объединяются. Фрагменты одного ответа доставляются по порядку; между двумя из них может прийти изменение настроек или будильник.

Background delivery of a response can be interrupted. A button press, screen switch, application-list reload or delivery to another application can unload the instance and drop the remaining pieces. Only <code>app_on_terminate()</code> is called. The poll is repeated after one minute, or after its interval when that is shorter.
Фоновая доставка ответа может прерваться. Нажатие кнопки, смена экрана, перечитывание списка приложений или доставка другому приложению могут выгрузить экземпляр и отбросить оставшиеся части. Вызывается только <code>app_on_terminate()</code>. Опрос повторяется через минуту или через свой интервал, если он короче.

State
Состояние

Global variables are kept until the application is unloaded. It is unloaded when it leaves the screen and after a background delivery ends. A streamed response keeps the same instance between chunks; it also handles intervening events for that application.
Глобальные переменные сохраняются до выгрузки приложения. Оно выгружается при уходе с экрана и по завершении фоновой доставки. При потоковом ответе один экземпляр остаётся загруженным между частями; он также обрабатывает промежуточные события этого приложения.

State is loaded in <code>app_on_load()</code> and saved in <code>app_on_terminate()</code>, the last call of every instance that was not stopped for a fault. A value that must survive a power loss is saved immediately after it changes.
Состояние загружается в <code>app_on_load()</code> и сохраняется в <code>app_on_terminate()</code> - последнем вызове каждого экземпляра, не остановленного из-за сбоя. Значение, которое должно пережить отключение питания, сохраняется сразу после изменения.

Use session memory for temporary UI state: the current page, selected row or unfinished edit. Up to 128 bytes (<code>HOST_SESSION_MAX</code>) survive unloads while the application remains in the navigation stack. It is saved in <code>app_on_blur()</code> and read in <code>app_on_focus()</code>, with <code>app_session_save()</code> and <code>app_session_load()</code>. It is cleared when the application leaves the stack, when it is opened again from the menu, and by a restart. An instance loaded for a background call can read it and cannot change it.
Используйте память сессии для временного состояния интерфейса: текущей страницы, выбранной строки или незавершённого ввода. До 128 байт (<code>HOST_SESSION_MAX</code>) сохраняются при выгрузке, пока приложение остаётся в стеке навигации. Сохраняйте их в <code>app_on_blur()</code>, восстанавливайте в <code>app_on_focus()</code> через <code>app_session_save()</code> и <code>app_session_load()</code>. Сессия очищается при выходе приложения из стека, повторном открытии из меню и перезапуске. Фоновый экземпляр может читать её, но не менять.

Use <code>time_now()</code> for timestamps that must span restarts. Store <code>time_boot_id()</code> beside an uptime value to detect an earlier boot and discard that value. The boot id is a random nonzero 32-bit value; equality does not guarantee that no restart occurred.
Для меток времени, сохраняемых между перезапусками, используйте <code>time_now()</code>. Вместе со временем работы сохраняйте <code>time_boot_id()</code>, чтобы обнаружить предыдущий запуск и отбросить старое значение. Идентификатор запуска - случайное ненулевое 32-битное число; совпадение не гарантирует отсутствия перезапуска.

For larger temporary state, such as a packed game board, use <code>scene_state_set()</code> and <code>scene_state_get()</code>. Perinkpheral OS allocates up to <code>HOST_SCENE_STATE_MAX</code> (1024) bytes on demand. This buffer is independent of the smaller session and follows the same lifetime and access rules. Both calls require firmware 0.1.34 or later.
Для более объёмного временного состояния, например упакованного игрового поля, используйте <code>scene_state_set()</code> и <code>scene_state_get()</code>. Perinkpheral OS выделяет до <code>HOST_SCENE_STATE_MAX</code> (1024) байт по запросу. Этот буфер хранится отдельно от меньшей сессии и подчиняется тем же правилам срока хранения и доступа. Для обоих вызовов нужна прошивка 0.1.34 или новее.

The session is attached after app_on_load() returns. Read it in app_on_focus() or a background delivery handler; session_set() in app_on_load() returns HOST_ERR_ARGUMENT.
Сессия подключается после возврата из app_on_load(). Читайте её в app_on_focus() или обработчике фоновой доставки; session_set() в app_on_load() возвращает HOST_ERR_ARGUMENT.

Navigation and refresh
Навигация и обновление экрана

Navigation is organized as a stack. The menu is at the bottom. An application opened from the menu is placed on top. A notification, a Perinkpheral OS question or an application that requested the screen is placed above the current screen.
Навигация организована как стек. Внизу находится меню. Приложение, открытое из меню, помещается сверху. Уведомление, вопрос Perinkpheral OS или приложение, запросившее экран, помещается над текущим экраном.

The top entry is removed by a short press of BACK. The stack is cleared and the menu is opened by a long press of BACK.
Верхний элемент снимается коротким нажатием BACK. Длинным нажатием BACK стек очищается и открывается меню.

Only the top entry is loaded. An application lower in the stack is unloaded; its state is restored when it returns to the top.
Загружен только верхний элемент. Приложение ниже в стеке выгружено; его состояние восстанавливается при возврате на вершину.

The panel is controlled by Perinkpheral OS. Each new frame is compared with the frame on the panel, and only the changed area is sent. A refresh without a button press is postponed if the previous one was too recent.
Панелью управляет Perinkpheral OS. Каждый новый кадр сравнивается с кадром на панели, передаётся только изменившаяся область. Обновление без нажатия кнопки откладывается, если предыдущее было слишком недавно.

A complete frame is always shown. Refresh timing is decided by Perinkpheral OS.
На панели всегда показан целый кадр. Момент обновления определяется Perinkpheral OS.

Setting placeholders
Подстановки настроек

<code>{{key}}</code> reads the application KV store, including undeclared keys; an absent declared setting uses its manifest default. The value is substituted, percent-encoded: every character except letters, digits and <code>- . _ ~</code> becomes <code>%XX</code>, <b>including <code>/</code></b>. One setting is one path segment: <code>owner/name</code> requires two settings, <code>/repos/{{owner}}/{{name}}</code>. A leading <code>url</code> setting and a <code>link</code> setting are inserted unchanged. A <code>list</code> setting is inserted as its items, each encoded, with commas between them: <code>symbols={{tickers}}</code> becomes <code>symbols=AAPL,MSFT</code>. A poll with an empty setting in its URL or headers fails with <code>HOST_FAILED_NOT_READY</code>; a token in a header is therefore required.
<code>{{key}}</code> читает KV-хранилище приложения, включая необъявленные ключи; отсутствующая объявленная настройка берётся из значения по умолчанию в манифесте. Значение подставляется с процентным кодированием: каждый символ, кроме букв, цифр и <code>- . _ ~</code>, становится <code>%XX</code>, <b>включая <code>/</code></b>. Одна настройка - один сегмент пути: для <code>owner/name</code> нужны два ключа, <code>/repos/{{owner}}/{{name}}</code>. Начальная настройка <code>url</code> и настройка <code>link</code> вставляются без изменений. Настройка <code>list</code> вставляется поэлементно с кодированием и запятыми между элементами: <code>symbols={{tickers}}</code> превращается в <code>symbols=AAPL,MSFT</code>. Пустая настройка в URL или заголовке опроса даёт <code>HOST_FAILED_NOT_READY</code>; поэтому токен в заголовке обязателен.

Polls are numbered from 0 in the order of the list. Handlers receive this number.
Опросы нумеруются с 0 в порядке списка. Этот номер получают обработчики.

A path follows the response from its top: <code>[0]</code> and <code>[*]</code> may stand together in one path, <code>chart.result[0].closes[*]</code>. With an empty list Perinkpheral OS attempts one poll with <code>answer_item()</code> equal to -1. It fails with <code>HOST_FAILED_NOT_READY</code> if substitution needs the unset list value; a fixed URL that does not reference the list can still be requested.
Путь отсчитывается от начала ответа: <code>[0]</code> и <code>[*]</code> могут быть в одном пути, <code>chart.result[0].closes[*]</code>. При пустом списке Perinkpheral OS пытается выполнить один опрос с <code>answer_item()</code>, равным -1. Он завершается с <code>HOST_FAILED_NOT_READY</code>, если подстановка требует пустое значение списка; фиксированный URL без ссылки на список может быть запрошен.

Surface and colour
Поверхность и цвет

The origin is the top left corner of the surface. <code>gfx_width()</code> and <code>gfx_height()</code> return its size. Use these values for layout.
Начало координат - левый верхний угол поверхности. <code>gfx_width()</code> и <code>gfx_height()</code> возвращают её размер. Используйте эти значения для компоновки.

Drawing calls work inside <code>app_on_draw()</code>. The surface is white at the start of each call. In any other handler, the drawing calls of <code>gfx_*</code> and <code>ui_*</code> return <code>HOST_ERR_NOT_DRAWING</code>; measuring text and fonts works anywhere. Drawing is clipped to the surface.
Вызовы отрисовки работают внутри <code>app_on_draw()</code>. В начале каждого вызова поверхность белая. В любом другом обработчике вызовы отрисовки <code>gfx_*</code> и <code>ui_*</code> возвращают <code>HOST_ERR_NOT_DRAWING</code>; измерение текста и шрифтов работает везде. Отрисовка обрезается по границам поверхности.

<code>gfx_set_color()</code> sets the colour for the following calls, from <code>HOST_PAPER</code> (0) to <code>HOST_INK</code> (16). The colour is <code>HOST_INK</code> at the start of each <code>app_on_draw()</code>. Intermediate values are dithered greys. Use greys for filled areas only: thin lines and small text become unreadable.
<code>gfx_set_color()</code> задаёт цвет для последующих вызовов, от <code>HOST_PAPER</code> (0) до <code>HOST_INK</code> (16). В начале каждого <code>app_on_draw()</code> цвет равен <code>HOST_INK</code>. Промежуточные значения - оттенки серого, получаемые дизерингом. Используйте серый только для заливок: тонкие линии и мелкий текст становятся нечитаемыми.

The standard margin is <code>HOST_UI_MARGIN</code> (16 px). Use it at the left and right edges.
Стандартное поле - <code>HOST_UI_MARGIN</code> (16 пикселей). Используйте его у левого и правого краёв.

Fonts
Шрифты

A font constant selects a size. The typeface is a user setting: Departure Mono (monospaced) or Jersey (proportional). Character widths differ between the two, so layout is based on measured widths.
Константа шрифта задаёт размер. Гарнитура - настройка пользователя: Departure Mono (моноширинная) или Jersey (пропорциональная). Ширина символов у них разная, поэтому компоновка строится на измеренной ширине.

Measure text with <code>gfx_text_width()</code>, <code>gfx_font_height()</code>, <code>gfx_font_ascent()</code> and <code>gfx_font_cap_height()</code>.
Измеряйте текст вызовами <code>gfx_text_width()</code>, <code>gfx_font_height()</code>, <code>gfx_font_ascent()</code> и <code>gfx_font_cap_height()</code>.

Each cell gives the value for Departure Mono, then for Jersey.
В каждой ячейке значение для Departure Mono, затем для Jersey.

The <code>y</code> argument of <code>gfx_draw_text()</code> is the top of the line. The baseline is at <code>y + ascent</code>; the top of the capitals is at <code>y + ascent - cap_height</code>.

Добавляйте <code>HOST_FONT_TABULAR</code> к шрифту для чисел, меняющихся на месте, например часов или обратного отсчёта. Все цифры получают одинаковую ширину. Флаг принимает любой вызов с аргументом шрифта. При измерении передавайте тот же флаг.

<code>gfx_fit_text()</code> shortens a text to a given width and appends "...". It cuts between characters, so the result is valid UTF-8.
<code>gfx_fit_text()</code> сокращает текст до заданной ширины и добавляет "...". Обрезка идёт по границе символа, поэтому результат остаётся корректным UTF-8.

Text beyond ASCII
Текст за пределами ASCII

Displayed text is UTF-8. Perinkpheral OS draws each character using the first available option:
Отображаемый текст - UTF-8. Для каждого символа Perinkpheral OS использует первый доступный вариант:

The glyph of the character. Printable ASCII is always available. Extended Latin, Cyrillic and Greek are available when the user has installed the glyph pack (Settings, Language, on the device's web page).
Глиф символа. Печатные символы ASCII доступны всегда. Расширенная латиница, кириллица и греческий доступны, если пользователь установил пакет глифов («Настройки», «Язык» на веб-странице устройства).

An ASCII transliteration: "Moskva", "Strasse", "Athina". Typographic dashes and quotes become plain ones.
Транслитерация в ASCII: "Moskva", "Strasse", "Athina". Типографские тире и кавычки заменяются простыми.

Вопросительный знак.

The degree sign is built in at every size.
Знак градуса встроен во все размеры.

The width of a text depends on which option was used. Always measure a text before placing it.
Ширина текста зависит от использованного способа. Всегда измеряйте текст перед размещением.

User-visible manifest text has both a character limit and a UTF-8 byte limit of twice that character limit. A title is at most 23 characters and 46 bytes. A field of the contract, such as a notice's line, has a size in bytes, and holds half as many two-byte characters as one-byte characters.
Текст манифеста для пользователя ограничен и числом символов, и числом байт UTF-8, равным удвоенному лимиту символов. Название содержит до 23 символов и 46 байт. Поле контракта, например строка уведомления, имеет размер в байтах и вмещает вдвое меньше двухбайтовых символов, чем однобайтовых.

Pictures and icons
Картинки и иконки

Perinkpheral OS provides 49 built-in icons: Perinkpheral OS's own, the weather, the things of a home and the sky. Each icon is on a grid of 11 x 11 cells, and many are also drawn on 22 and 44 cells. An application uses them instead of drawing its own.
Perinkpheral OS предоставляет 49 встроенных иконок: системные, погодные, домашние и астрономические. Каждая нарисована на сетке 11 x 11 клеток, многие ещё и на 22 и 44 клетках. Приложение берёт их, а не рисует свои.

<code>gfx_draw_icon()</code> draws an icon with a cell size of 1 to 16 pixels. <code>ui_draw_icon()</code> draws an icon at one of three standard sizes: 22, 44 or 99 px. Perinkpheral OS picks the finest drawing that fits at two pixels per cell or more, so lines keep the weight of the text and curves stay smooth at large sizes. <code>gfx_icon_ink()</code> gives the pixels an icon covers, to align it by what is visible.
<code>gfx_draw_icon()</code> рисует иконку с клеткой от 1 до 16 пикселей. <code>ui_draw_icon()</code> рисует иконку одного из трёх стандартных размеров: 22, 44 или 99 px. Perinkpheral OS берёт самый подробный рисунок, который помещается при двух пикселях на клетку или больше: толщина линий соответствует толщине штрихов текста, а кривые на больших размерах остаются гладкими. <code>gfx_icon_ink()</code> сообщает, какие пиксели занимает иконка, для выравнивания по границам видимого рисунка.

7. Buttons
7. Кнопки

The buttons are, in order: UP, OK, DOWN, BACK. Perinkpheral OS uses them the same way on every screen. Applications should keep these meanings.
Кнопки по порядку: UP, OK, DOWN, BACK. Perinkpheral OS использует их одинаково на всех экранах. Приложениям следует сохранять эти значения.

Each press produces two kinds of events. The raw events are <code>KEYDOWN</code> and <code>KEYUP</code>. The interpreted events are <code>PRESSED</code>, sent when a short press ends, and <code>LONG_PRESSED</code>, sent after 600 ms while the button is still held. A long press does not produce <code>PRESSED</code>.
Каждое нажатие порождает события двух видов. Низкоуровневые события - <code>KEYDOWN</code> и <code>KEYUP</code>. Интерпретированные события - <code>PRESSED</code>, отправляется по окончании короткого нажатия, и <code>LONG_PRESSED</code>, отправляется через 600 мс, пока кнопка ещё удерживается. Длинное нажатие не порождает <code>PRESSED</code>.

Most applications handle only <code>PRESSED</code> and <code>LONG_PRESSED</code>.
Большинство приложений обрабатывает только <code>PRESSED</code> и <code>LONG_PRESSED</code>.

<code>kv_get()</code> and <code>kv_set()</code> read and write small values by key. Each application has a private namespace.

9. Network
9. Сеть

All network access goes through Perinkpheral OS. The application describes a request; Perinkpheral OS performs it and delivers the response. Perinkpheral OS performs one request at a time for the whole device. Responses normally reach the application on or off screen. A poll refused before starting because there is no network or insufficient session memory is reported only while its application is on screen.
Весь доступ к сети идёт через Perinkpheral OS. Приложение описывает запрос; Perinkpheral OS выполняет его и доставляет ответ. На всём устройстве одновременно выполняется один запрос. Ответы обычно доставляются и на экране, и вне его. Отказ в опросе до начала запроса из-за отсутствия сети или памяти сессии сообщается только приложению на экране.

Network availability is reported in the response: a request made without a network fails with <code>HOST_FAILED_NO_NETWORK</code>.
О доступности сети сообщает ответ: запрос, сделанный без сети, завершается ошибкой <code>HOST_FAILED_NO_NETWORK</code>.

Process each piece when it arrives and keep only the data to display. Use a state machine, the SDK's <code>json_pick</code> or a custom parser. A response can be several megabytes; the application has 64 KB. <code>json_pick</code> takes list paths too, with a buffer the application gives (section 23).
Обрабатывайте каждый кусок по приходу и храните только данные для показа. Используйте конечный автомат, <code>json_pick</code> из SDK или свой разборщик. Ответ может занимать несколько мегабайт; у приложения 64 КБ. <code>json_pick</code> принимает и пути списков, с буфером, который даёт приложение (раздел 23).

Replace the displayed data only on <code>HOST_DATA_LAST</code>. Delivery can stop without a last piece and without a failure (section 3). <code>HOST_DATA_FIRST</code> always starts a new response.
Заменяйте отображаемые данные только по <code>HOST_DATA_LAST</code>. Доставка может прекратиться без последнего фрагмента и без ошибки (раздел 3). <code>HOST_DATA_FIRST</code> всегда начинает новый ответ.

Inside the handler, <code>answer_info(&amp;response, sizeof response)</code> copies response metadata and returns the bytes written: status, Content-Length, Content-Type, ETag, Last-Modified, Location, Link and Retry-After. В обработчике <code>answer_info(&amp;response, sizeof response)</code> копирует метаданные ответа и возвращает число записанных байт: status, Content-Length, Content-Type, ETag, Last-Modified, Location, Link и Retry-After. Копируется не больше размера структуры Perinkpheral OS; отсутствующие поля обнулены, кроме length, равного -1 при отсутствии длины.

Successful response chunks share metadata. A terminal HOST_DATA_FAILED callback may have no metadata: answer_info() returns the failure code as status, length -1 and empty header strings. Invalid or incomplete picked JSON gives HOST_FAILED_NO_ANSWER even if an HTTP response arrived.
Успешные части ответа имеют общие метаданные. Завершающий вызов с HOST_DATA_FAILED может не иметь метаданных: answer_info() возвращает код ошибки как status, length -1 и пустые строки заголовков. Неверный или незавершённый JSON с извлечением значений даёт HOST_FAILED_NO_ANSWER, даже если HTTP-ответ получен.

Requests from code
Запросы из кода

Requests are allowed only to the hosts listed in the manifest. <code>{{key}}</code> placeholders work in the URL and in header values, so the code does not need to read the token.
Запросы разрешены только на адреса, перечисленные в манифесте. Подстановки <code>{{key}}</code> работают в URL и в значениях заголовков, поэтому коду не нужно читать токен.

An application can have 16 requests waiting (<code>HOST_HTTP_PENDING_MAX</code>). Queue additional requests as responses arrive. Applications and polls take turns while queued work remains valid. <code>HOST_ERR_NO_SPACE</code> means that 16 are waiting, or that the device has no memory for another.
У приложения может ждать 16 запросов (<code>HOST_HTTP_PENDING_MAX</code>). Добавляйте следующие запросы по мере прихода ответов. Приложения и опросы обслуживаются по очереди, пока ожидающие запросы остаются действительными. <code>HOST_ERR_NO_SPACE</code> означает, что ждут 16 или что у устройства нет памяти ещё на один.

Perinkpheral OS sends <code>User-Agent: perinkpheral</code>. A <code>User-Agent</code> header given by the application replaces it, in a poll and in a request.
Perinkpheral OS отправляет <code>User-Agent: perinkpheral</code>. Заголовок <code>User-Agent</code> от приложения заменяет его, в опросе и в запросе.

A response to a request from code that was interrupted (section 3) is dropped: the request is not repeated. Ask again from <code>app_on_terminate()</code> or later if the response is still needed.
Прерванный ответ на запрос из кода (раздел 3) отбрасывается: запрос не повторяется. Если ответ ещё нужен, запросите снова из <code>app_on_terminate()</code> или позже.

Perinkpheral OS follows up to three redirects for a <code>GET</code>. A redirect to a host outside the list fails with <code>HOST_FAILED_NOT_ALLOWED</code>. A request of another method is sent once; its redirect response is delivered as the response.
Для <code>GET</code> Perinkpheral OS выполняет до трёх перенаправлений. Перенаправление на адрес вне списка завершается ошибкой <code>HOST_FAILED_NOT_ALLOWED</code>. Запрос другим методом отправляется один раз; ответ с перенаправлением доставляется как ответ на запрос.

<code>poll_run(n)</code> requests poll <code>n</code> through the shared queue without waiting for a response; repeated pending requests are coalesced, for example when the user presses a refresh button. <code>poll_set_interval(n, seconds)</code> changes the interval of a poll from code, for example to honour a Retry-After header.
<code>poll_run(n)</code> запрашивает опрос <code>n</code> через общую очередь без ожидания ответа; повторные ожидающие запросы объединяются, например при нажатии кнопки обновления. <code>poll_set_interval(n, seconds)</code> меняет интервал опроса из кода, например по заголовку Retry-After.

For http_send(), URL substitution and the initial host check happen before queuing. An unset URL value returns HOST_ERR_ARGUMENT without a callback. The expanded destination stays queued. Before sending, it is authorized again and headers are filled from the same current KV snapshot. A settings change that disallows the old destination gives HOST_FAILED_NOT_ALLOWED; queued requests are never silently retargeted. Missing or invalid header values give HOST_FAILED_NOT_READY. Once prepared, the request keeps its snapshot during transmission. URLs fit in 511 bytes; header values in 255 bytes; body bytes are copied at queue time.
Для http_send() URL подставляется и впервые проверяется до постановки в очередь. Неустановленное значение URL даёт HOST_ERR_ARGUMENT без обработчика ответа. В очереди остаётся раскрытый адрес. Перед отправкой адрес проверяется заново, а заголовки заполняются из того же текущего снимка KV. Если изменение настроек запретило прежний адрес, приходит HOST_FAILED_NOT_ALLOWED; запрос никогда молча не перенаправляется на новый сервер. Отсутствующие или недопустимые значения заголовков дают HOST_FAILED_NOT_READY. Подготовленный запрос сохраняет свой снимок при передаче. URL вмещает 511 байт, значение заголовка - 255 байт; тело копируется при постановке в очередь.

The 16-request ceiling is per application, with no reserved slots. All queued requests share a 16 KB budget for queue records, URLs, headers and bodies. HOST_ERR_NO_SPACE may occur before sixteen requests are waiting. A raw header name is at most 31 bytes; its value is at most 255 bytes.
Лимит 16 ожидающих запросов задан на приложение без резервирования мест. Все запросы делят 16 KB на записи очереди, URL, заголовки и тела. HOST_ERR_NO_SPACE возможен и при меньшем числе запросов. Имя исходного заголовка - до 31 байта, значение - до 255 байт.

11. Время

<code>time_now()</code> returns Unix time in seconds. It returns 0 until the device has obtained the time. The application must handle this case.
<code>time_now()</code> возвращает время Unix в секундах. Возвращает 0, пока устройство не получило время. Приложение обязано обрабатывать этот случай.

Display local time. Perinkpheral OS owns the time zone. <code>time_local()</code> returns the current local date and time, <code>time_local_at()</code> converts any moment, and <code>time_from_local()</code> converts a local date and time back to Unix time, for example for <code>alarm_set_at()</code>.
Отображайте местное время. Часовым поясом управляет Perinkpheral OS. <code>time_local()</code> возвращает текущие местные дату и время, <code>time_local_at()</code> преобразует любой момент, <code>time_from_local()</code> преобразует местные дату и время обратно во время Unix, например для <code>alarm_set_at()</code>.

<code>time_text()</code> formats a moment as text in the device's language. Applications do not need their own names of days and months. Formats: "15:04", "Fri 13 Nov", "Friday", "Fri", "13 November", and a relative form: "15:04", "Tmrw 15:04", "Sat 15:04", "21 Nov".
<code>time_text()</code> форматирует момент времени как текст на языке устройства. Собственные названия дней и месяцев приложениям не нужны. Форматы: "15:04", "Пт 13 ноя", "Пятница", "Пт", "13 ноября" и относительная форма: "15:04", "Завтра 15:04", "Сб 15:04", "21 ноя".

To be called when the clock is set or changed, declare the <code>time_changed</code> intent.
Чтобы получать вызов при установке или изменении часов, объявите интент <code>time_changed</code>.

Форматы времени

Examples use local time 15:04 on Friday 13 November 2026. Relative examples assume today is Thursday 12 November 2026.
В примерах местное время - 15:04 в пятницу 13 ноября 2026 года. Для относительных форматов сегодня - четверг 12 ноября 2026 года.

12. Languages
12. Языки

Application string keys match <code>[a-z][a-z0-9_]*</code>. Generated constants use <code>STR_</code> followed by the uppercase key.
Ключи строк приложения соответствуют <code>[a-z][a-z0-9_]*</code>. Сгенерированные константы начинаются с <code>STR_</code>, затем идёт ключ в верхнем регистре.

An application displays its text in the language of the device. The developer provides the translations. Perinkpheral OS loads the translation for the current language.
Приложение отображает свой текст на языке устройства. Переводы предоставляет разработчик. Perinkpheral OS загружает перевод для текущего языка.

<code>strings/</code> is optional. When it is there, <code>en.json</code> is required in it. English is compiled into the module and is used when a translation is unavailable. Every other file contains exactly the same keys. The key <code>manifest</code> is allowed in translations only (see below).
<code>strings/</code> необязательна. Если она есть, в ней обязателен <code>en.json</code>. Английский встраивается в модуль и используется, когда перевода нет. Каждый другой файл содержит ровно те же ключи. Ключ <code>manifest</code> допустим только в переводах (см. ниже).

When Perinkpheral OS loads the application, it copies the string table of the device's language into the application's memory, over the English table. <code>app_string()</code> then returns the translated text with no extra call.
При загрузке приложения Perinkpheral OS копирует таблицу строк на языке устройства в память приложения поверх английской. После этого <code>app_string()</code> возвращает переведённый текст без дополнительного вызова.

<code>text_fill()</code> replaces <code>{0}</code>, <code>{1}</code> in a string with numbers or texts. A translation can place them in any order. Write each string in one form for all numbers, for example "min".
<code>text_fill()</code> заменяет <code>{0}</code>, <code>{1}</code> в строке числами или текстами. Перевод может располагать их в любом порядке. Пишите каждую строку в одной форме для всех чисел, например "min".

The <code>manifest</code> key of a translation contains the translated parts of the manifest: the title, the title and help of each setting, and labels for the options of a choice. The stored option value does not change; only its label is translated.
Ключ <code>manifest</code> перевода содержит переводимые части манифеста: название, заголовок и пояснение каждой настройки, подписи вариантов выбора. Хранимое значение варианта не меняется; переводится только его подпись.

The build fails if a language is not listed in <code>sdk/languages.json</code> (27 languages, two-letter codes), if a translation has a missing or an extra key, or if a string contains a character that the glyph packs of the language do not cover.
Сборка завершается ошибкой, если языка нет в <code>sdk/languages.json</code> (27 языков, двухбуквенные коды), если в переводе не хватает ключа или есть лишний, либо если строка содержит символ, которого нет в пакетах глифов языка.

Translated text may be longer or shorter than English. Check every supported language with both typefaces, including long labels and truncated text.
Перевод может быть длиннее или короче оригинала. Проверяйте каждый поддерживаемый язык с обеими гарнитурами, включая длинные подписи и усечённый текст.

13. Design rules
13. Правила проектирования

These rules apply to all applications. Perinkpheral OS's own screens follow them. Most are conventions; Perinkpheral OS checks only a few.
Эти правила относятся ко всем приложениям. Экраны самой Perinkpheral OS им следуют. Большинство из них - соглашения; Perinkpheral OS проверяет лишь некоторые.

Screen content
Содержимое экрана

Show one main value per screen.
Показывайте одно главное значение на экране.

The device is read from about a metre, in about a second. Choose the main value, draw it largest, and keep everything else small.
Устройство читают примерно с метра, примерно за секунду. Выберите главное значение, нарисуйте его самым крупным, остальное оставьте мелким.

Keep screens static.
Делайте экраны статичными.

Change a screen only when its data changes. A bar shows a quantity. To indicate work in progress, show a notice with <code>is_working</code>.
Меняйте экран, только когда меняются его данные. Полоса показывает количество. Для индикации работы показывайте сообщение с <code>is_working</code>.

Redraw only when the content changes.
Перерисовывайте только при изменении содержимого.

A timer should request a redraw only if the picture will differ. A clock redraws once a minute, on the minute. By default Perinkpheral OS allows one refresh per minute that was not caused by a button press. Design for this rate.
Таймер должен запрашивать перерисовку, только если изображение изменится. Часы перерисовываются раз в минуту, на границе минуты. По умолчанию Perinkpheral OS допускает одно обновление в минуту без нажатия кнопки. Проектируйте под эту частоту.

Draw black on white.
Рисуйте чёрным по белому.

Use ink on paper. Use grey for filled areas only. Use white text on a black bar only for the selected item or for new information.
Используйте чернила на бумаге. Серый используйте только для заливок. Белый текст на чёрной полосе используйте только для выбранного элемента или новой информации.

Keep interface text short and standard.
Делайте текст интерфейса коротким и стандартным.

Use common words: "Save", "Remove", "Not set up". If a label needs an explanation, change the label.
Используйте общепринятые слова: «Сохранить», «Удалить», «Настройте». Если подпись требует пояснения, смените подпись.

Minimize code size before data size.
Сокращайте сначала размер кода, затем размер данных.

Each byte of executed code uses about four bytes of the interpreter's 64 KB. Each byte of data uses one byte of the 64 KB page. Prefer a table to a chain of <code>if</code> statements, the kit to custom drawing, <code>pick</code> to a custom parser, and <code>time_text()</code> to custom date formatting.
Каждый байт исполненного кода занимает около четырёх байт из 64 КБ интерпретатора. Каждый байт данных занимает один байт страницы 64 КБ. Предпочитайте таблицу цепочке операторов <code>if</code>, Kit - собственной отрисовке, <code>pick</code> - собственному разборщику, <code>time_text()</code> - собственному форматированию дат.

Keep shared helpers out of line.
Не встраивайте общие вспомогательные функции.

Mark a small helper that is called from many places with <code>__attribute__((noinline))</code> and compare the build reports.
Небольшую вспомогательную функцию, вызываемую из многих мест, помечайте <code>__attribute__((noinline))</code> и сравнивайте отчёты сборки.

Store pictures as bits.
Храните картинки в битах.

Put pictures in <code>pictures/</code>. Put large pictures in <code>files/</code>.
Размещайте картинки в <code>pictures/</code>. Большие картинки размещайте в <code>files/</code>.

Process responses as a stream.
Обрабатывайте ответы потоком.

Process a response as it arrives and keep only the data to display. Call <code>app_alloc_mark()</code> before allocating temporary buffers with <code>app_alloc()</code>. When finished, call <code>app_alloc_release(mark)</code> to release every allocation made since that mark (section 23).
Обрабатывайте ответ по мере поступления и оставляйте только данные для отображения. Перед выделением временных буферов через <code>app_alloc()</code> вызывайте <code>app_alloc_mark()</code>. По завершении вызывайте <code>app_alloc_release(mark)</code>, освобождая всё, что выделено после отметки (раздел 23).

State and time
Состояние и время

Save state before every unload.
Сохраняйте состояние перед каждой выгрузкой.

Keep persistent data in the store. Save navigation and unfinished editing state to the session in <code>app_on_blur()</code>; restore it in <code>app_on_focus()</code>. Opening from the menu starts a new session.
Постоянные данные храните в хранилище. Навигацию и незавершённый ввод сохраняйте в сессии в <code>app_on_blur()</code>; восстанавливайте в <code>app_on_focus()</code>. Открытие из меню начинает новую сессию.

Keep the displayed data until new data is complete.
Сохраняйте показанные данные, пока новые не получены целиком.

After a failed or interrupted request, keep the previous data on the screen.
После неудавшегося или прерванного запроса оставляйте на экране прежние данные.

Explain an empty screen.
Объясняйте пустой экран.

Call <code>ui_draw_reason()</code> to show "Not set up", "No network" or "Loading".
Вызывайте <code>ui_draw_reason()</code>, чтобы показать "Настройте", "Нет сети" или "Загрузка".

Handle an unknown or changed clock.
Обрабатывайте неизвестное или изменённое время.

Handle <code>time_now() == 0</code>. Use <code>alarm_set()</code> for a delay ("in ten minutes") and <code>alarm_set_at()</code> for a clock time ("at seven").
Обрабатывайте <code>time_now() == 0</code>. Используйте <code>alarm_set()</code> для задержки («через десять минут») и <code>alarm_set_at()</code> для времени по часам («в семь»).

Interaction and data
Взаимодействие и данные

Take text input on the web page.
Принимайте текстовый ввод на веб-странице.

Declare text such as a token, an address or a city as a manifest setting; the user enters it on the device's web page. On the device, let the user choose from a few values with UP and DOWN.
Текст - токен, адрес, город - объявляйте настройкой в манифесте; пользователь вводит его на веб-странице устройства. На устройстве давайте пользователю выбор из нескольких значений кнопками UP и DOWN.

Take the screen rarely.
Занимайте экран редко.

Use a notification only for events the user asked to be told about, such as a timer or a meeting. Let other information wait until the user looks.
Используйте уведомление только для событий, о которых пользователь просил сообщать, например таймер или встреча. Остальная информация ждёт, пока пользователь посмотрит на устройство.

Send user data only where the user directs.
Отправляйте данные пользователя только туда, куда он указал.

List only the hosts the application needs. Use a <code>url</code> setting for the user's own server. Use a <code>secret</code> setting for a token and send it through a header placeholder.
Перечисляйте только те адреса, которые нужны приложению. Для собственного сервера пользователя используйте настройку типа <code>url</code>. Для токена используйте настройку типа <code>secret</code> и передавайте его подстановкой в заголовке.

Poll no more often than the data changes.
Опрашивайте не чаще, чем меняются данные.

Offer the interval as a setting with a reasonable default. On battery power Perinkpheral OS limits every poll to one per five minutes.
Предлагайте интервал как настройку с разумным значением по умолчанию. При питании от батареи Perinkpheral OS ограничивает каждый опрос одним разом в пять минут.

This part summarizes Perinkpheral OS calls and exports for ABI 3. Signatures are abbreviated. Include <code>sdk/host_api.h</code>; complete types, constants and declarations are in <code>sdk/host/*.h</code>.
Этот раздел кратко описывает вызовы Perinkpheral OS и экспорты для ABI 3. Сигнатуры сокращены. Подключайте <code>sdk/host_api.h</code>; полные типы, константы и объявления находятся в <code>sdk/host/*.h</code>.

Команды называют предмет, затем действие (<code>kv_get</code>, <code>gfx_draw_text</code>); запросы называют предмет и то, что требуется узнать (<code>gfx_width</code>, <code>time_now</code>); события, вызываемые Perinkpheral OS, используют <code>app_on_&lt;what happened&gt;</code> (<code>app_on_load</code>, <code>app_on_picked</code>).

ABI 3 compatibility
Совместимость ABI 3

ABI 3 starts with firmware 0.1.30. Existing names, wasm types, privileges, constants, layouts and meanings remain available in later firmware. A changed signature or meaning requires a new ABI; HOST_SINCE_ stamps only entries added after the ABI 3 floor, 0.1.30. Firmware releases and ABI generations are independent. Missing exports remain optional.
ABI 3 начинается с прошивки 0.1.30. Существующие имена, типы wasm, привилегии, константы, раскладки и смысл вызовов сохраняются в следующих прошивках. Изменение сигнатуры или смысла требует нового ABI; HOST_SINCE_ отмечает только дополнения после нижней границы ABI 3, версии 0.1.30. Выпуски прошивки и поколения ABI независимы. Отсутствующие экспорты остаются необязательными.

The supported set is {3}. The manifest ABI is retained through loading and checked before execution. The device page uses ABI membership and the firmware minimum together for Install, Update and Update all; /api/status reports supported_abis. The downloaded manifest is authoritative. Catalog publishing copies identity and compatibility metadata from the packaged manifest.
Поддерживается множество {3}. ABI манифеста передаётся до загрузки и проверяется до выполнения кода. Страница устройства вместе проверяет принадлежность ABI и минимум прошивки для Install, Update и Update all; /api/status сообщает supported_abis. Окончательное решение принимается по загруженному манифесту. При публикации каталога данные об идентичности и совместимости берутся из упакованного манифеста.

tools/perinkpheral contract snapshot records the contract in sdk/abi/3.txt and package hashes separately in sdk/abi/3/fixtures.txt; contract check verifies both in host tests and CI. Recorded entries cannot change or disappear; additions are allowed. Snapshot writes refuse changes too. Frozen packages in sdk/abi/3/ are test inputs and are never rebuilt by tests: Probe, Hello, Settings with translations, and Hello state (presses = 42 as four little-endian bytes). The ABI 3 floor is 0.1.30, the first firmware of ABI 3.
tools/perinkpheral contract snapshot записывает контракт в sdk/abi/3.txt, а хеши пакетов отдельно в sdk/abi/3/fixtures.txt; contract check проверяет оба файла в нативных тестах и CI. Записанные элементы нельзя менять или удалять; дополнения разрешены. Запись снимка тоже отклоняет изменения. Зафиксированные пакеты в sdk/abi/3/ служат входными данными тестов, которые никогда их не пересобирают: Probe, Hello, Settings с переводами и состояние Hello (presses = 42 в четырёх байтах little-endian). Нижняя граница ABI 3 - 0.1.30, первая прошивка с ABI 3.

Binary representation and buffers
Бинарное представление и буферы

The contract uses wasm32 little-endian C layouts and two's complement signed integers. Pointers are unsigned 32-bit memory offsets; zero is NULL. 32-bit integers and pointers have size/alignment 4, 64-bit integers 8, bytes 1. Structs keep C field order and natural alignment with trailing padding. sdk/abi/3.txt records every size, alignment, field type and offset. String-table size, count and offsets are little-endian 16-bit words. Picture dimensions are bytes; bitmap rows are high-bit first and padded to whole bytes.
Контракт использует раскладку C для wasm32 little-endian и дополнительный код для знаковых целых. Указатель - беззнаковое 32-битное смещение в памяти; ноль означает NULL. Размер и выравнивание 32-битных целых и указателей равны 4, 64-битных целых - 8, байтов - 1. Структуры сохраняют порядок полей C, естественное выравнивание и конечное заполнение. sdk/abi/3.txt записывает каждый размер, выравнивание, тип и смещение поля. Размер, число строк и смещения таблицы строк - 16-битные слова little-endian. Размеры картинок задаются байтами; строки битовой карты идут старшим битом вперёд и дополняются до целого числа байтов.

Input buffers are consumed or copied before an import returns. Perinkpheral OS retains only the exported app_data_buffer and app_strings_buffer storage for the loaded instance; keep that storage valid until unload. Handler data is valid until the handler returns. Lengths and capacities count bytes. Text output has no appended NUL, except fixed host_answer_info_t string fields. Negative lengths/capacities or invalid memory ranges give HOST_ERR_ARGUMENT.
Входные буферы используются или копируются до возврата импорта. Perinkpheral OS сохраняет только хранилища экспортов app_data_buffer и app_strings_buffer на время жизни загруженного экземпляра; они должны быть доступны до выгрузки. Данные обработчика действительны до его возврата. Длины и ёмкости считаются в байтах. К текстовому результату не добавляется NUL, кроме строковых полей фиксированного host_answer_info_t. Отрицательные длины и ёмкости и недопустимые диапазоны памяти дают HOST_ERR_ARGUMENT.

kv_get, answer_value, answer_element, session_get, sys_info, sys_app_title and sys_setting_get fail with HOST_ERR_NO_SPACE without copying when the value does not fit. Capacity zero is valid for an empty value. gfx_fit_text also requires room for its whole fitted result and copies nothing on error. text_fill and time_text instead truncate between UTF-8 characters and return bytes copied; text_fill accepts zero capacity, time_text rejects it. Read/format/measurement errors leave outputs untouched; file_read may have copied a prefix before a storage error. answer_info copies min(capacity, Perinkpheral OS's struct size), accepts zero and leaves later bytes untouched. sys_app_list writes up to capacity ids but returns the total count; capacity zero is allowed.
kv_get, answer_value, answer_element, session_get, sys_info, sys_app_title и sys_setting_get возвращают HOST_ERR_NO_SPACE, ничего не копируя, если значение не помещается. Нулевая ёмкость допустима для пустого значения. gfx_fit_text также требует места для всего подогнанного результата и ничего не копирует при ошибке. text_fill и time_text вместо этого обрезают между символами UTF-8 и возвращают число скопированных байтов; text_fill принимает нулевую ёмкость, time_text отказывает. Ошибки чтения, форматирования и измерения оставляют выходы неизменными; file_read может скопировать начало до ошибки хранилища. answer_info копирует min(capacity, размер структуры Perinkpheral OS), принимает ноль и не трогает последующие байты. sys_app_list записывает не более capacity идентификаторов, но возвращает общее число; нулевая ёмкость допустима.

Install and update are consumed after loading and before the callback, including a missing callback or a trap in app_on_load or the callback. A load failure leaves the notification pending until startup or application-list reload. Updated means another module-and-manifest package id, regardless of version-string ordering.
Уведомления об установке и обновлении считаются доставленными после загрузки и до обработчика, в том числе при отсутствии обработчика или trap в app_on_load либо обработчике. Ошибка загрузки оставляет уведомление до запуска устройства или перечитывания списка приложений. Обновление означает другой идентификатор пакета из модуля и манифеста, независимо от порядка строк версий.

Only HOST_DATA_LAST makes a streamed answer whole. HOST_DATA_FAILED may follow earlier pieces and invalidates them all. An interrupted answer may end with neither flag. Piece boundaries are unspecified, even inside a UTF-8 character or a document marker. Keep the previous displayed result until LAST.
Только HOST_DATA_LAST делает потоковый ответ полным. HOST_DATA_FAILED может прийти после предыдущих фрагментов и отменяет их все. Прерванный ответ может закончиться без обоих флагов. Границы фрагментов не определены, даже внутри символа UTF-8 или маркера документа. Сохраняйте предыдущий показанный результат до LAST.

Rendering keeps the existing rules: combined redraw flags choose CLEAN before NO_BLINK before SOON; QUESTION is independent. When dithering is disabled, gfx_set_color shades 1..7 become paper and 8..15 ink. Icon first/last ink coordinates are inclusive; text end_x is exclusive.
Отрисовка сохраняет существующие правила: совместные флаги перерисовки выбирают CLEAN раньше NO_BLINK, затем SOON; QUESTION независим. При отключённом дизеринге оттенки gfx_set_color 1..7 становятся бумагой, 8..15 - чернилами. Первые и последние координаты чернил иконки включительны; end_x текста исключителен.

System settings expose only the explicit page-visible keys listed in sdk/host/sys.h, which specifies types, units, inclusive ranges, special values and restart behaviour for each. Unknown and internal keys, including refresh_min_button_ms, return HOST_ERR_NOT_FOUND for get, set and range. The Wi-Fi SSID is read-only here; the password cannot be read or written here (HOST_ERR_ARGUMENT). Network changes use the page or SYS_DO_FORGET_NETWORK.
Системные настройки открывают только явно перечисленные видимые на странице ключи sdk/host/sys.h, где для каждого указаны тип, единицы, включительные диапазоны, специальные значения и необходимость перезапуска. Неизвестные и внутренние ключи, включая refresh_min_button_ms, возвращают HOST_ERR_NOT_FOUND для get, set и range. SSID Wi-Fi здесь доступен только для чтения; пароль нельзя ни читать, ни писать (HOST_ERR_ARGUMENT). Сеть изменяют через страницу или SYS_DO_FORGET_NETWORK.

From firmware 0.1.51, <code>answer_header(name, name_length, occurrence, value, capacity)</code> reads a response header inside either data handler. Names are case-insensitive HTTP tokens, 1–63 bytes. Occurrence starts at 0; repeated Set-Cookie fields remain separate, in arrival order. The result is the value length without a terminating NUL. A missing field returns HOST_ERR_NOT_FOUND; invalid arguments return HOST_ERR_ARGUMENT. A value that does not fit returns HOST_ERR_NO_SPACE without writing.
Начиная с прошивки 0.1.51, <code>answer_header(name, name_length, occurrence, value, capacity)</code> читает заголовок ответа в любом обработчике данных. Имя — HTTP-токен длиной 1–63 байта, без учёта регистра. Номер вхождения начинается с 0; повторные Set-Cookie сохраняются отдельно, в порядке получения. Результат — длина значения без завершающего NUL. Для отсутствующего поля возвращается HOST_ERR_NOT_FOUND, для неверных аргументов — HOST_ERR_ARGUMENT. Если значение не помещается, возвращается HOST_ERR_NO_SPACE без записи.

Perinkpheral OS keeps up to 1024 bytes of headers, counting each name, value and two NUL separators. If the complete set does not fit, every answer_header call returns HOST_ERR_NO_SPACE, including fields received before overflow. answer_info remains available. Only the final response after redirects is exposed. No cookies are sent or stored automatically.

После перенаправлений доступен только конечный ответ. Cookie не отправляются и не сохраняются автоматически.
