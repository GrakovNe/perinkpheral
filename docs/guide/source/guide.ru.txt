1. Overview
1. Обзор

perINKpheral is a desk display: a 4.2" black-and-white e-paper panel with four buttons, built on an ESP32-C6. Information intended for reading at a glance is displayed: time, weather, the next meeting, the state of a home.
perINKpheral - настольный дисплей: чёрно-белая панель E-Ink 4,2" с четырьмя кнопками на базе ESP32-C6. Отображается информация, рассчитанная на чтение с одного взгляда: время, погода, ближайшая встреча, состояние дома.

The firmware is called the <i>host</i>. The host draws the menu and its own notices. Every other screen is an <i>application</i>, Settings and About among them: they are system applications, carried in the firmware. Applications are installed from a catalog; the firmware is not reflashed.
Прошивка называется <i>хостом</i>. Хост рисует меню и свои уведомления. Все остальные экраны - <i>приложения</i>, в том числе Настройки и О системе: это системные приложения, встроенные в прошивку. Приложения устанавливаются из каталога; прошивка при этом не перезаписывается.

An application consists of a WebAssembly module and a manifest. The module is written in C against a single header, <code>sdk/host_api.h</code>, and is executed by an interpreter (wasm3) inside the host.
Приложение состоит из модуля WebAssembly и манифеста. Модуль пишется на C с одним заголовочным файлом, <code>sdk/host_api.h</code>, и исполняется интерпретатором (wasm3) внутри хоста.

The host's own pages, Settings and About, are built as applications with the same header.
Собственные страницы хоста, «Настройки» и «О системе», собраны как приложения с тем же заголовочным файлом.

Дисплей: 400 x 300 пикселей, 1 бит, оттенки серого дизерингом, частичное обновление примерно за 0,5 с

How an application runs
Как работает приложение

An application is a set of exported handlers with fixed names. A handler is called by the host when an event occurs: a button press, a timer, incoming data, a request to draw.
Приложение - это набор экспортируемых обработчиков с фиксированными именами. Обработчик вызывается хостом при наступлении события: нажатие кнопки, таймер, поступление данных, запрос на отрисовку.

The application's state is updated in a handler, and a redraw is requested. <code>app_on_draw()</code> is called by the host when a frame is needed. Refresh timing and method are decided by the host.
Состояние приложения изменяется в обработчике, после чего запрашивается перерисовка. <code>app_on_draw()</code> вызывается хостом, когда нужен кадр. Момент и способ обновления экрана определяются хостом.

One application is loaded at a time. An application is unloaded when it leaves the screen. Persistent state is kept in the application's store; global variables are kept until the unload.
Одновременно загружено одно приложение. Приложение выгружается, когда уходит с экрана. Постоянное состояние хранится в хранилище приложения; глобальные переменные сохраняются до выгрузки.

Handler guarantees
Гарантии для обработчиков

Handlers are run one at a time, each to completion. Locking is unnecessary.
Обработчики выполняются по одному, каждый до завершения. Блокировки не нужны.

A handler is limited to 3 seconds. A handler that exceeds the limit, or traps (for example, on an invalid pointer), is stopped. The application is then terminated and an error screen is shown. The host is unaffected.
Обработчик ограничен 3 секундами. Обработчик, превысивший лимит или вызвавший ловушку (например, на неверном указателе), останавливается. Приложение завершается, показывается экран ошибки. Хост продолжает работу.

Handlers return <code>void</code>. A redraw, the screen or an exit is obtained with a request. Requests are applied after the handler returns.
Обработчики возвращают <code>void</code>. Перерисовка, экран или выход получаются запросом. Запросы применяются после возврата из обработчика.

<code>app_init()</code> is called before any other handler of an instance.
<code>app_init()</code> вызывается раньше любого другого обработчика экземпляра.

Button events are delivered in order; 16 can wait, and one more is lost. Pending timers with the same number are merged. The pieces of one response are delivered in order; a settings change or an alarm may be delivered between two of them.
События кнопок доставляются по порядку; ждать могут 16, следующее теряется. Ожидающие таймеры с одним номером объединяются. Фрагменты одного ответа доставляются по порядку; между двумя из них может прийти изменение настроек или будильник.

State
Состояние

State is loaded in <code>app_init()</code> and saved in <code>app_on_terminate()</code>, the last call of every instance that was not stopped for a fault. A value that must survive a power loss is saved immediately after it changes.
Состояние загружается в <code>app_init()</code> и сохраняется в <code>app_on_terminate()</code> - последнем вызове каждого экземпляра, не остановленного из-за сбоя. Значение, которое должно пережить отключение питания, сохраняется сразу после изменения.

Navigation and refresh
Навигация и обновление экрана

Navigation is organized as a stack. The menu is at the bottom. An application opened from the menu is placed on top. A notification, a host question or an application that requested the screen is placed above the current screen.
Навигация организована как стек. Внизу находится меню. Приложение, открытое из меню, помещается сверху. Уведомление, вопрос хоста или приложение, запросившее экран, помещается над текущим экраном.

The top entry is removed by a short press of BACK. The stack is cleared and the menu is opened by a long press of BACK.
Верхний элемент снимается коротким нажатием BACK. Длинным нажатием BACK стек очищается и открывается меню.

Only the top entry is loaded. An application lower in the stack is unloaded; its state is restored when it returns to the top.
Загружен только верхний элемент. Приложение ниже в стеке выгружено; его состояние восстанавливается при возврате на вершину.

The panel is controlled by the host. Each new frame is compared with the frame on the panel, and only the changed area is sent. A refresh without a button press is postponed if the previous one was too recent.
Панелью управляет хост. Каждый новый кадр сравнивается с кадром на панели, передаётся только изменившаяся область. Обновление без нажатия кнопки откладывается, если предыдущее было слишком недавно.

A complete frame is always shown. Refresh timing is decided by the host.
На панели всегда показан целый кадр. Момент обновления определяется хостом.

The buttons are, in order: UP, OK, DOWN, BACK. The host uses them the same way on every screen. Applications should keep these meanings.
Кнопки по порядку: UP, OK, DOWN, BACK. Хост использует их одинаково на всех экранах. Приложениям следует сохранять эти значения.

Each press produces two kinds of events. The raw events are <code>KEYDOWN</code> and <code>KEYUP</code>. Most applications handle only <code>PRESSED</code> and <code>LONG_PRESSED</code>.
Большинство приложений обрабатывает только <code>PRESSED</code> и <code>LONG_PRESSED</code>.

11. Time

13. Design rules
13. Правила проектирования

These rules apply to all applications. The host's own screens follow them. Most are conventions; the host checks only a few.
Эти правила относятся ко всем приложениям. Экраны самого хоста им следуют. Большинство из них - соглашения; хост проверяет лишь некоторые.

The device is read from about a metre, in about a second. Choose the main value, draw it largest, and keep everything else small.
Устройство читают примерно с метра, примерно за секунду. Выберите главное значение, нарисуйте его самым крупным, остальное оставьте мелким.

Change a screen only when its data changes. A bar shows a quantity. To indicate work in progress, show a notice with <code>is_working</code>.
Меняйте экран, только когда меняются его данные. Полоса показывает количество. Для индикации работы показывайте сообщение с <code>is_working</code>.

A timer should request a redraw only if the picture will differ. A clock redraws once a minute, on the minute. By default the host allows one refresh per minute that was not caused by a button press. Design for this rate.
Таймер должен запрашивать перерисовку, только если изображение изменится. Часы перерисовываются раз в минуту, на границе минуты. По умолчанию хост допускает одно обновление в минуту без нажатия кнопки. Проектируйте под эту частоту.

Setting placeholders
Подстановки настроек

<code>{{key}}</code> of any setting is replaced by the stored value, percent-encoded: every character except letters, digits and <code>- . _ ~</code> becomes <code>%XX</code>, <b>including <code>/</code></b>. One setting is one path segment: <code>owner/name</code> requires two settings, <code>/repos/{{owner}}/{{name}}</code>. A leading <code>url</code> setting and a <code>link</code> setting are inserted unchanged. A <code>list</code> setting is inserted as its items, each encoded, with commas between them: <code>symbols={{tickers}}</code> becomes <code>symbols=AAPL,MSFT</code>. A poll with an empty setting in its URL or headers fails with <code>HOST_FAILED_NOT_READY</code>; a token in a header is therefore required.
<code>{{key}}</code> любой настройки заменяется её значением с процентным кодированием: всё, кроме букв, цифр и <code>- . _ ~</code>, становится <code>%XX</code>, <b>включая <code>/</code></b>. Одна настройка - один сегмент пути: для <code>owner/name</code> нужны две настройки, <code>/repos/{{owner}}/{{name}}</code>. Начальная настройка <code>url</code> и настройка <code>link</code> вставляются без изменения. Настройка <code>list</code> вставляется как закодированные элементы через запятую: <code>symbols={{tickers}}</code> становится <code>symbols=AAPL,MSFT</code>. Опрос с пустой настройкой в URL или заголовках завершается с <code>HOST_FAILED_NOT_READY</code>; токен в заголовке поэтому обязателен.

A path follows the response from its top: <code>[0]</code> and <code>[*]</code> may stand together in one path, <code>chart.result[0].closes[*]</code>. With an empty list the host attempts one poll with <code>data_item()</code> equal to -1. It fails with <code>HOST_FAILED_NOT_READY</code> if substitution needs the unset list value; a fixed URL that does not reference the list can still be requested.
Путь отсчитывается от начала ответа: <code>[0]</code> и <code>[*]</code> могут быть в одном пути, <code>chart.result[0].closes[*]</code>. При пустом списке хост пытается выполнить один опрос с <code>data_item()</code>, равным -1. Он завершается с <code>HOST_FAILED_NOT_READY</code>, если подстановка требует пустое значение списка; фиксированный URL без ссылки на список может быть запрошен.

Значения формы настроек должны быть печатным ASCII; для списков также разрешён перевод строки между элементами.

A picked path has at most 63 bytes, each property name at most 31 ASCII bytes, and at most eight property or array-index levels. For example, <code>a.b[0]</code> uses three levels. The build and device reject paths beyond these limits.
Путь для извлечения содержит не более 63 байт, каждое имя свойства - не более 31 байта ASCII, а число уровней свойств и индексов массива не превышает восьми. Например, <code>a.b[0]</code> занимает три уровня. Сборка и устройство отклоняют пути, превышающие эти ограничения.

Time arguments to <code>time_local_at()</code>, <code>time_text()</code> and <code>alarm_set_at()</code> accept Unix seconds 1767225600 through 4102444800: 2026-01-01 through 2100-01-01 UTC, inclusive (<code>HOST_TIME_MIN</code> through <code>HOST_TIME_MAX</code>). Outside this range they return <code>HOST_ERR_ARGUMENT</code> and leave destinations unchanged. <code>time_from_local()</code> applies the same range to the Unix moment after normalizing the local fields; an out-of-range result leaves its destination unchanged.
Аргументы времени в <code>time_local_at()</code>, <code>time_text()</code> и <code>alarm_set_at()</code> принимают секунды Unix от 1767225600 до 4102444800: с 2026-01-01 до 2100-01-01 UTC включительно (от <code>HOST_TIME_MIN</code> до <code>HOST_TIME_MAX</code>). За пределами этого диапазона вызовы возвращают <code>HOST_ERR_ARGUMENT</code> и не изменяют выходные данные. <code>time_from_local()</code> проверяет тот же диапазон для момента Unix после нормализации полей местного времени; результат за пределами диапазона не изменяет выходное значение.

Paths have at most 63 bytes, property names at most 31 ASCII bytes, and extraction reaches at most eight containers; each property or array index uses one level. Deeper containers are skipped. Closing brackets must match their containers, and literals must be numbers, true, false or null. Validation keeps one bit per container and rejects nesting beyond 64. A broken document makes <code>json_pick_finish()</code> return false.
Пути содержат не более 63 байт, имена свойств - не более 31 байта ASCII, а извлечение охватывает не более восьми контейнеров; каждое свойство или индекс массива занимает один уровень. Более глубокие контейнеры пропускаются. Закрывающие скобки должны соответствовать контейнерам, а литералы должны быть числами, true, false или null. Проверка хранит один бит на контейнер и отклоняет вложенность свыше 64. Для повреждённого документа <code>json_pick_finish()</code> возвращает false.

<code>app_fixed_parse()</code> keeps up to 18 significant digits. It refuses a number if discarded digits would change the result at the requested decimals, including after exponent scaling, and leaves the destination unchanged. Digits below that precision still round half away from zero.
<code>app_fixed_parse()</code> сохраняет до 18 значащих цифр. Если отброшенные цифры изменили бы результат при запрошенном числе знаков после запятой, в том числе после применения экспоненты, функция отклоняет число и не изменяет выходное значение. Цифры ниже этой точности по-прежнему округляются от нуля при равенстве половине.
