Part I. Datasheet

1. Overview

perINKpheral is a desk display: a 4.2" black-and-white e-paper panel with four buttons, built on an ESP32-C6. Information intended for reading at a glance is displayed: time, weather, the next meeting, the state of a home.

Perinkpheral OS is a specialized operating system for e-paper, built on FreeRTOS/ESP-IDF. It draws the menu and its own notices. Its other screens are applications, Settings and About among them: they are system applications, carried in the firmware. Applications are installed from a catalog; the firmware is not reflashed.

An independent recovery image installs firmware updates and runs no applications. Ordinary OTA replaces only the main firmware and preserves installed packages and their data.

An application consists of a WebAssembly module and a manifest. The module is written in C against a single header, sdk/host_api.h, and is executed by an interpreter (wasm3) inside Perinkpheral OS.

Perinkpheral OS's own pages, Settings and About, are built as applications with the same header.

Features

  • Display: 400 x 300 pixels, 1 bit, dithered greys, partial refresh in about 0.5 s
  • Input: four buttons; short press, long press, key down and key up events
  • Sandbox: 64 KB of private memory; network access through Perinkpheral OS only
  • Network: HTTP and HTTPS requests performed by Perinkpheral OS, as scheduled polls or on request from the code
  • Data: Perinkpheral OS extracts values and lists from JSON responses; any response can be streamed in 1 KB pieces
  • Background work: responses, alarms and device events are delivered while the application is off the screen
  • Storage: a key-value store, kept across restarts and reinstalls, and files, kept across restarts
  • Design system: lists, notices, pickers, cells and a button row, drawn by Perinkpheral OS
  • Screen inversion: an application can invert its complete screen, including Perinkpheral OS header
  • Notifications: shown by Perinkpheral OS over any screen
  • Settings: declared in the manifest, edited on the device's web page
  • Localization: strings per language, loaded by Perinkpheral OS; Extended Latin, Cyrillic and Greek
  • Tools: build, check and measure an application; control a device over the network

How an application runs

An application is a set of exported handlers with fixed names. A handler is called by Perinkpheral OS when an event occurs: a button press, a timer, incoming data, a request to draw.

The application's state is updated in a handler, and a redraw is requested. app_on_draw() is called by Perinkpheral OS when a frame is needed. Refresh timing and method are decided by Perinkpheral OS.

One application is loaded at a time. An application is unloaded when it leaves the screen. Persistent state is kept in the application's store; global variables are kept until the unload.

3. Execution model

An application is loaded for a handler call and can be unloaded after it.

Handler guarantees

  • Handlers are run one at a time, each to completion. Locking is unnecessary.
  • A handler is limited to 3 seconds. A handler that exceeds the limit, or traps (for example, on an invalid pointer), is stopped. The application is then terminated and an error screen is shown. Perinkpheral OS is unaffected.
  • Handlers return void. A redraw, the screen or an exit is obtained with a request. Requests are applied after the handler returns.
  • app_on_load() is called before any other handler of an instance.
  • Button events are delivered in order; 16 can wait, and one more is lost. Pending timers with the same number are merged. The pieces of one response are delivered in order; a settings change or an alarm may be delivered between two of them.
  • Background delivery of a response can be interrupted. A button press, screen switch, application-list reload or delivery to another application can unload the instance and drop the remaining pieces. Only app_on_terminate() is called. The poll is repeated after one minute, or after its interval when that is shorter.

State

Global variables are kept until the application is unloaded. It is unloaded when it leaves the screen and after a background delivery ends. A streamed response keeps the same instance between chunks; it also handles intervening events for that application.

State is loaded in app_on_load() and saved in app_on_terminate(), the last call of every instance that was not stopped for a fault. A value that must survive a power loss is saved immediately after it changes.

Use session memory for temporary UI state: the current page, selected row, unfinished edit or a packed game board. Up to 1024 bytes (HOST_SESSION_MAX) survive unloads while the application remains in the navigation stack; Perinkpheral OS allocates them on demand, and session_set() returns HOST_ERR_NO_SPACE, keeping the previous value, if it cannot. Firmware before 0.1.61 keeps 128 bytes: an application that keeps more sets "firmware": "0.1.61" in its manifest. It is saved in app_on_blur() and read in app_on_focus(), with app_session_save() and app_session_load(). It is cleared when the application leaves the stack, when it is opened again from the menu, and by a restart. An instance loaded for a background call can read it and cannot change it.

Use time_now() for timestamps that must span restarts. Store time_boot_id() beside an uptime value to detect an earlier boot and discard that value. The boot id is a random nonzero 32-bit value; equality does not guarantee that no restart occurred.

The session is attached after app_on_load() returns. Read it in app_on_focus() or a background delivery handler; session_set() in app_on_load() returns HOST_ERR_ARGUMENT.

Navigation and refresh

Navigation is organized as a stack. The menu is at the bottom. An application opened from the menu is placed on top. A notification, a Perinkpheral OS question or an application that requested the screen is placed above the current screen.

The top entry is removed by a short press of BACK. The stack is cleared and the menu is opened by a long press of BACK.

Only the top entry is loaded. An application lower in the stack is unloaded; its state is restored when it returns to the top.

The panel is controlled by Perinkpheral OS. Each new frame is compared with the frame on the panel, and only the changed area is sent. A refresh without a button press is postponed if the previous one was too recent.

A complete frame is always shown. Refresh timing is decided by Perinkpheral OS.

Part II. Development guide

4. A first application

Requirements

  • wasi-sdk 34 or newer. It provides clang for the wasm32 target. Set WASI_SDK_PATH to its location.
  • Java 21 or later, for tools/perinkpheral: the tools, built on first use. The CLion plugin bundles these Java tools; its setup downloads the SDK and wasi-sdk.
  • A checkout of the perinkpheral repository. It contains sdk/ and tools/.
  • A device on the same network, running a debug firmware image with development tools enabled. The device shows its address on the second page of About. Set PERINKPHERAL_HOST to this address.
  • Without a device: the simulator (section 14). It needs a C compiler to be built, or comes built with the CLion plugin.

Create, build, run

Run these commands from the repository root.

Create

tools/perinkpheral new my-app --author "Your name" --title "My app"

Run on a device

tools/perinkpheral run my-app

Run in the simulator

tools/perinkpheral sim my-app

Open the development page

tools/perinkpheral serve my-app

run builds the application, uploads it, restarts the device and opens the application. The firmware is not reflashed.

The build treats compiler warnings as errors (-Wall -Wextra -Werror). An unused parameter is marked with (void)name;.

serve starts a local web page with the live screen, the four buttons, the device log and a Run button. The arrow keys, Enter and Backspace act as the buttons. The page accepts requests from itself only, as the device does.

IDE setup

new also creates a CMakeLists.txt in the application's folder. Open this folder in an IDE that supports CMake, such as CLion or VS Code.

The IDE resolves the SDK headers and the generated strings.h and pictures.h. The project has four build targets: my-app (build), my-app-package (build and check the package, with the report), my-app-run (build and run on the device) and my-app-serve (the live page). The IDE compiles with the flags of the build (tools/perinkpheral flags) and produces the same module.

The generated headers are made when the project is configured, and again when it is reloaded after strings/ or pictures/ change; the CLion plugin remakes them on every change. A string the code does not use yet, or a translation that lacks a string, is accepted in them; the build refuses both.

Set WASI_SDK_PATH and PERINKPHERAL_HOST in the CMake environment of the IDE.

The perINKpheral plugin for CLion (repository perinkpheral-clion-plugin) does this setup itself. It downloads the SDK and wasi-sdk on request, opens an application folder as a CMake project, and adds two run configurations: on the device and in the simulator. Its device window shows the live screen, the buttons, the log and the status of the device or the simulator.

Sample application

#include "app_text.h"
#include "host_api.h"

#define MARGIN HOST_UI_MARGIN

static const char PRESSES_KEY[] = "presses";
#define PRESSES_KEY_LENGTH ((int32_t)sizeof PRESSES_KEY - 1)

static int32_t presses;

static void draw_line(int32_t line, const char *text)
{
    int32_t line_height = gfx_font_height(HOST_FONT_TEXT);
    gfx_draw_text(MARGIN, MARGIN + line * line_height, HOST_FONT_TEXT, text, app_text_length(text));
}

void app_on_load(void)                 /* load the state from the store */
{
    kv_get(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_terminate(void)         /* save the state before the unload */
{
    kv_set(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_button(int32_t event)   /* update the state, request a redraw */
{
    switch (event) {
    case BTN_UP_PRESSED:
    case BTN_OK_PRESSED:
    case BTN_DOWN_PRESSED:
        presses++;
        screen_redraw(HOST_REDRAW_NORMAL);
        break;
    }
}

void app_on_draw(void)              /* draw the whole frame from the state */
{
    char       counter_buffer[32];
    app_text_t counter;
    app_text_start(&counter, counter_buffer, sizeof counter_buffer);
    app_text_add(&counter, "Presses: ");
    app_text_add_number(&counter, presses);

    draw_line(0, "Hello from wasm");
    draw_line(2, counter_buffer);
}

BACK is handled by Perinkpheral OS here: a short press of BACK closes an application that has no app_on_back() export.

Setting placeholders

{{key}} reads the application KV store, including undeclared keys; an absent declared setting uses its manifest default. The value is substituted, percent-encoded: every character except letters, digits and - . _ ~ becomes %XX, including /. One setting is one path segment: owner/name requires two settings, /repos/{{owner}}/{{name}}. A leading url setting and a link setting are inserted unchanged. A list setting is inserted as its items, each encoded, with commas between them: symbols={{tickers}} becomes symbols=AAPL,MSFT. A poll with an empty setting in its URL or headers fails with HOST_FAILED_NOT_READY; a token in a header is therefore required.

Settings

Settings are declared in the manifest. The device's web page builds the settings form from the manifest alone. Each value is stored as text in the application's store, under the key of the setting.

The application reads a setting with kv_get() and the key of the setting.

Settings form values must be printable ASCII; list values also allow line breaks between items.

When the user saves the form, Perinkpheral OS calls app_on_settings() and repeats all polls immediately.

  • url and link settings are read-only for the application: kv_set() on their keys fails. When the user changes such a setting, Perinkpheral OS erases the secrets that were not entered again, so a token stays with the server it was entered for.
  • title is 1 to 31 characters. help is up to 95 characters.

Non-list defaults are nonempty strings, including number and toggle defaults. Secret and place settings cannot have defaults. A list default must contain at least one item.

Perinkpheral OS validates supplied settings before writing, but writes are not transactional. A storage failure can leave some values changed. If at least one write succeeds, app_on_settings() is delivered and polls are requested again, even after a partially failed save.

6. Screen

Surface and colour

  • The origin is the top left corner of the surface. gfx_width() and gfx_height() return its size. Use these values for layout.
  • Drawing calls work inside app_on_draw(). The surface is white at the start of each call. In any other handler, the drawing calls of gfx_* and ui_* return HOST_ERR_NOT_DRAWING; measuring text and fonts works anywhere. Drawing is clipped to the surface.
  • gfx_set_color() sets the colour for the following calls, from HOST_PAPER (0) to HOST_INK (16). The colour is HOST_INK at the start of each app_on_draw(). Intermediate values are dithered greys. Use greys for filled areas only: thin lines and small text become unreadable.
  • The standard margin is HOST_UI_MARGIN (16 px). Use it at the left and right edges.

Whole-screen inversion

Since firmware 0.1.54, screen_set_inverted(inverted) selects normal colours with 0 or inverted colours with any nonzero value. It returns HOST_OK; changing the value requests a redraw. Draw on the usual white surface with the usual colours. Perinkpheral OS inverts the completed frame, including its header, the bottom margin and any footer or telemetry drawn by the application. Full-screen applications use the same call.

The preference belongs to the current scene. It survives temporary unloads for background delivery and covering the scene with another screen, and is restored when the scene returns. Closing the scene clears it. It does not change the menu, other applications or a global theme. The call is allowed outside app_on_draw(); background handlers return HOST_OK but cannot change the retained foreground preference.

Displayed text is UTF-8. Perinkpheral OS draws each character using the first available option:

  3. A question mark.

The width of a text depends on which option was used. Always measure a text before placing it.

7. Buttons

The buttons are, in order: UP, OK, DOWN, BACK. Perinkpheral OS uses them the same way on every screen. Applications should keep these meanings.

Each press produces two kinds of events. The raw events are KEYDOWN and KEYUP. The interpreted events are PRESSED, sent when a short press ends, and LONG_PRESSED, sent after 600 ms while the button is still held. A long press does not produce PRESSED.

Most applications handle only PRESSED and LONG_PRESSED.

The event value combines the button and the action. Each combination has a constant:

void app_on_button(int32_t event)
{
    switch (event) {
    case BTN_OK_PRESSED:       start();  break;
    case BTN_OK_LONG_PRESSED:  reset();  break;
    }
    screen_redraw(HOST_REDRAW_NORMAL);
}

8. Storage

Store

kv_get() and kv_set() read and write small values by key. Each application has a private namespace.

The store holds the application's state and its settings. Removal normally keeps the store for reinstall. Perinkpheral OS may reclaim stores belonging to removed applications when the stores partition is full. Removal with "forget" erases it immediately.

typedef struct { int32_t version; int32_t minutes; int64_t ends_at; } state_t;
static state_t state;

void app_on_load(void)
{
    if (kv_get("state", 5, &state, sizeof state) != sizeof state || state.version != 2) {
        state = (state_t){ .version = 2, .minutes = 25 };     /* no stored state, or an older version */
    }
}
  • Put a version field in every stored struct and check it on load. A newer version of the application will read data written by an older one.
  • Every write wears the flash memory. Write only when the data has changed. Do not write on every timer tick.
  • kv_set() with a length of 0 deletes the key.

Files

Use files for data that does not fit in a store value: a downloaded list, a cache, a picture.

file_read() and file_write() take an offset. A file can be read and extended in parts, so it never has to be held in memory in full.

The files from the files/ folder of the package are installed with the application.

  • Existing files remain unless an update supplies a file with the same name, which replaces it. Use names outside the package's filenames for writable caches. Files are removed with the application.
  • A write starts inside the file or at its end. To replace a file with a shorter one, delete it first: file_write() with length 0 at offset 0.
  • Writing needs "writes_files": true in the manifest. The total file quota is 32 KB, including packaged data files. Unused space in that quota is reserved for the application. At catalog installation the manifest also counts towards this limit.
  • Each file takes whole blocks of 4 KB of the 32 KB. Keep related records in one file.

9. Network

All network access goes through Perinkpheral OS. The application describes a request; Perinkpheral OS performs it and delivers the response. Perinkpheral OS performs one request at a time for the whole device. Responses normally reach the application on or off screen. A poll refused before starting because there is no network or insufficient session memory is reported only while its application is on screen.

Network availability is reported in the response: a request made without a network fails with HOST_FAILED_NO_NETWORK.

Numbers are integers. app_value_number() returns the value scaled by the requested number of decimals, rounded.

A path that is absent from the response has no value: app_value_number() returns false. An absent value means no data.

Lists

A path with [*] in place of one index is a list path: every element of that array, in order. app_value_count() returns the number of elements. app_value_series() converts them to numbers for ui_draw_chart():

/* "pick": ["quote.name", "quote.closes[*]"] */
static int32_t prices[HOST_CHART_VALUES_MAX];
static int32_t count;

void app_on_picked(int32_t request, int32_t http_status)
{
    int32_t item = answer_item();                                    /* which ticker of the list */
    if (http_status == 200) {
        count = app_value_series(1, 2, prices, HOST_CHART_VALUES_MAX);  /* hundredths; "null": a gap */
    }
}
  • A null element is kept, as a gap in the series, so that two lists of one array stay in step. An element without the rest of the path (items[*].title in an item without a title) is skipped.
  • The elements of one response take up to 8 KB as text (HOST_LIST_BYTES); each costs its length and 2 bytes. Elements beyond that are dropped and the log says so.
  • With more elements than the capacity, app_value_series() takes evenly spread elements, the first and the last among them.
  • A value goes to the first path that names it: a[*] before a[0] takes the element.

Numbers

Floating point is not available. A number is an integer with a fixed number of decimals: 356.27 is 35627 with 2 decimals. app_fixed.h reads, converts and writes such numbers in 64 bits:

Streamed responses

void app_on_data(int32_t request, const uint8_t *data, int32_t length, int32_t flags, int32_t http_status)
{
    if (flags & HOST_DATA_FAILED) {                /* failure without data; discard all preceding pieces: http_status is a HOST_FAILED_* code */
        last_status = http_status;
        return;
    }
    if (flags & HOST_DATA_FIRST) {                 /* the first piece carries the HTTP status */
        last_status = http_status;
        begin_reading();                           /* reset the parser */
    }
    read_piece(data, length);                      /* data is valid until the handler returns */
    if (flags & HOST_DATA_LAST) {
        take_what_was_read();                      /* the response is complete */
        screen_redraw(HOST_REDRAW_NORMAL);
    }
}
  • Process each piece when it arrives and keep only the data to display. Use a state machine, the SDK's json_pick or a custom parser. A response can be several megabytes; the application has 64 KB. json_pick takes list paths too, with a buffer the application gives (section 23).
  • Replace the displayed data only on HOST_DATA_LAST. Delivery can stop without a last piece and without a failure (section 3). HOST_DATA_FIRST always starts a new response.
  • Inside the handler, answer_info(&response, sizeof response) copies response metadata and returns the bytes written: status, Content-Length, Content-Type, ETag, Last-Modified, Location, Link and Retry-After. It copies at most Perinkpheral OS's struct size; absent fields are zeroed, except length is -1 when absent.

Successful response chunks share metadata. A terminal HOST_DATA_FAILED callback may have no metadata: answer_info() returns the failure code as status, length -1 and empty header strings. Invalid or incomplete picked JSON gives HOST_FAILED_NO_ANSWER even if an HTTP response arrived.

From firmware 0.1.51, answer_header(name, name_length, occurrence, value, capacity) reads a response header inside either data handler. Names are case-insensitive HTTP tokens, 1–63 bytes. Occurrence starts at 0; repeated Set-Cookie fields remain separate, in arrival order. The result is the value length without a terminating NUL. A missing field returns HOST_ERR_NOT_FOUND; invalid arguments return HOST_ERR_ARGUMENT. A value that does not fit returns HOST_ERR_NO_SPACE without writing.

Perinkpheral OS keeps up to 1024 bytes of headers, counting each name, value and two NUL separators. If the complete set does not fit, every answer_header call returns HOST_ERR_NO_SPACE, including fields received before overflow. answer_info remains available. Only the final response after redirects is exposed. No cookies are sent or stored automatically.

For authentication across background unloads, save a small session record with kv_set when the session changes, not on every poll. Include the server/account identity and handshake step; restore them on load. Clear the session when settings change or the server rejects it. Declare a cookie field as secret if it belongs in settings; stored values are not encrypted. session_set belongs to a scene and is not a background credential store.

Requests from code

enum { REQUEST_TOGGLE = HOST_REQUEST_FIRST };
static const char URL[]     = "{{server}}/api/services/light/toggle";
static const char HEADERS[] = "Authorization: Bearer {{token}}\nContent-Type: application/json";

http_send(REQUEST_TOGGLE, HOST_HTTP_POST, URL, sizeof URL - 1, HEADERS, sizeof HEADERS - 1,
             body, body_length);
  • Requests are allowed only to the hosts listed in the manifest. {{key}} placeholders work in the URL and in header values, so the code does not need to read the token.
  • An application can have 16 requests waiting (HOST_HTTP_PENDING_MAX). Queue additional requests as responses arrive. Applications and polls take turns while queued work remains valid. HOST_ERR_NO_SPACE means that 16 are waiting, or that the device has no memory for another.
  • Perinkpheral OS sends User-Agent: perinkpheral. A User-Agent header given by the application replaces it, in a poll and in a request.
  • A response to a request from code that was interrupted (section 3) is dropped: the request is not repeated. Ask again from app_on_terminate() or later if the response is still needed.
  • Perinkpheral OS follows up to three redirects for a GET. A redirect to a host outside the list fails with HOST_FAILED_NOT_ALLOWED. A request of another method is sent once; its redirect response is delivered as the response.
  • poll_run(n) requests poll n through the shared queue without waiting for a response; repeated pending requests are coalesced, for example when the user presses a refresh button. poll_set_interval(n, seconds) changes the interval of a poll from code, for example to honour a Retry-After header.

For http_send(), URL substitution and the initial host check happen before queuing. An unset URL value returns HOST_ERR_ARGUMENT without a callback. The expanded destination stays queued. Before sending, it is authorized again and headers are filled from the same current KV snapshot. A settings change that disallows the old destination gives HOST_FAILED_NOT_ALLOWED; queued requests are never silently retargeted. Missing or invalid header values give HOST_FAILED_NOT_READY. Once prepared, the request keeps its snapshot during transmission. URLs fit in 511 bytes; header values in 255 bytes; body bytes are copied at queue time.

The 16-request ceiling is per application, with no reserved slots. All queued requests share a 16 KB budget for queue records, URLs, headers and bodies. HOST_ERR_NO_SPACE may occur before sixteen requests are waiting. A raw header name is at most 31 bytes; its value is at most 255 bytes.

Certificate authorities of the application

Perinkpheral OS verifies HTTPS servers against the ESP-IDF's root certificate bundle. A server certified by an authority outside that set fails with HOST_FAILED_NOT_TRUSTED. An application that needs such a server brings the authority's root certificate in its package and names it in the manifest:

"certificates": ["russian-root-ca.pem"]          /* files/russian-root-ca.pem */
  • Each file is a root certificate of an authority, in PEM or DER, up to 4 KB. The build rejects a file that is missing, is not a certificate, is a server's certificate, or has expired.
  • The roots are trusted for this application's polls and requests only, in addition to the ESP-IDF's root certificate bundle. Other applications and Perinkpheral OS do not trust them.
  • The web page names the authorities before installation, as it does for system access, and on the application's card. The catalog index carries their names.
  • Obtain the root certificate from its authority and verify its fingerprint against that authority's published fingerprint.

11. Time

  • time_now() returns Unix time in seconds. It returns 0 until the device has obtained the time. The application must handle this case.
  • Display local time. Perinkpheral OS owns the time zone. time_local() returns the current local date and time, time_local_at() converts any moment, and time_from_local() converts a local date and time back to Unix time, for example for alarm_set_at().
  • time_text() formats a moment as text in the device's language. Applications do not need their own names of days and months. Formats: "15:04", "Fri 13 Nov", "Friday", "Fri", "13 November", and a relative form: "15:04", "Tmrw 15:04", "Sat 15:04", "21 Nov".

Application string keys match [a-z][a-z0-9_]*. Generated constants use STR_ followed by the uppercase key.

An application displays its text in the language of the device. The developer provides the translations. Perinkpheral OS loads the translation for the current language.

  • When Perinkpheral OS loads the application, it copies the string table of the device's language into the application's memory, over the English table. app_string() then returns the translated text with no extra call.
  • text_fill() replaces {0}, {1} in a string with numbers or texts. A translation can place them in any order. Write each string in one form for all numbers, for example "min".

  • The build fails if a language is not listed in sdk/languages.json (27 languages, two-letter codes), if a translation has a missing or an extra key, or if a string contains a character that the glyph packs of the language do not cover.
  • Translated text may be longer or shorter than English. Check every supported language with both typefaces, including long labels and truncated text.

13. Design rules

These rules apply to all applications. Perinkpheral OS's own screens follow them. Most are conventions; Perinkpheral OS checks only a few.

Screen content

Show one main value per screen. The device is read from about a metre, in about a second. Choose the main value, draw it largest, and keep everything else small.
Keep screens static. Change a screen only when its data changes. A bar shows a quantity. To indicate work in progress, show a notice with is_working.
Redraw only when the content changes. A timer should request a redraw only if the picture will differ. A clock redraws once a minute, on the minute. By default Perinkpheral OS allows one refresh per minute that was not caused by a button press. Design for this rate.
Draw black on white. Use ink on paper. Use grey for filled areas only. Use white text on a black bar only for the selected item or for new information.
Keep interface text short and standard. Use common words: "Save", "Remove", "Not set up". If a label needs an explanation, change the label.

Memory

Minimize code size before data size. Each byte of executed code uses about four bytes of the interpreter's 64 KB. Each byte of data uses one byte of the 64 KB page. Prefer a table to a chain of if statements, the kit to custom drawing, pick to a custom parser, and time_text() to custom date formatting.
Keep shared helpers out of line. Mark a small helper that is called from many places with __attribute__((noinline)) and compare the build reports.
Store pictures as bits. Put pictures in pictures/. Put large pictures in files/.
Process responses as a stream. Process a response as it arrives and keep only the data to display. Call app_alloc_mark() before allocating temporary buffers with app_alloc(). When finished, call app_alloc_release(mark) to release every allocation made since that mark (section 23).

State and time

Save state before every unload. Keep persistent data in the store. Save navigation and unfinished editing state to the session in app_on_blur(); restore it in app_on_focus(). Opening from the menu starts a new session.
Keep the displayed data until new data is complete. After a failed or interrupted request, keep the previous data on the screen.
Explain an empty screen. Call ui_draw_reason() to show "Not set up", "No network" or "Loading".
Handle an unknown or changed clock. Handle time_now() == 0. Use alarm_set() for a delay ("in ten minutes") and alarm_set_at() for a clock time ("at seven").

Interaction and data

Take text input on the web page. Declare text such as a token, an address or a city as a manifest setting; the user enters it on the device's web page. On the device, let the user choose from a few values with UP and DOWN.
Take the screen rarely. Use a notification only for events the user asked to be told about, such as a timer or a meeting. Let other information wait until the user looks.
Send user data only where the user directs. List only the hosts the application needs. Use a url setting for the user's own server. Use a secret setting for a token and send it through a header placeholder.
Poll no more often than the data changes. Offer the interval as a setting with a reasonable default. On battery power Perinkpheral OS limits every poll to one per five minutes.

15. Publishing

A device installs applications from catalogs. A catalog is a folder of static files with an index. It can be hosted anywhere that serves HTTPS, for example as raw files of a git repository or as a static site.

Publish to your GitHub repository

Install Git and GitHub CLI. Sign in, then create a public repository once. Replace OWNER with your GitHub username.

gh auth login
gh repo create OWNER/my-perink-apps --public

Publish the applications in your local apps folder:

tools/perinkpheral publish apps --repo OWNER/my-perink-apps

The command builds the applications, checks their packages and updates catalog/ on the repository's default branch. The repository must be public and your account must have write access. Files outside catalog/ stay unchanged.

Each run replaces the whole catalog. Supply all folders whose applications you want to publish; applications omitted from them are removed from the catalog. Repeating the command without changes creates no commit.

Copy the repository link printed by the command. On the device page, open Catalog → Sources (the gear), add the link and save. The applications appear with an Install button.

For an update, increase version in manifest.json, run publish again and refresh the catalog on the device page.

Other hosting

To host the catalog elsewhere, build it locally and upload the output folder to an HTTPS server:

tools/perinkpheral catalog my-apps --out catalog       # build all applications in the folder
                                                       # output: catalog/catalog.json, one folder per application
  • The output folder is created anew on every run. It must be empty or an earlier catalog, and must not contain the applications.
  • The index lists the name, title, version and icon of each application, and its files with their sizes and SHA-256 hashes. The device accepts a file only if both the size and the hash match.
  • Trust model: HTTPS to a source that the user selected, plus the sandbox. Packages are unsigned.
  • The official catalog is the perinkpheral-apps repository, with eighteen applications. It is the first source on every device. The user can add up to three HTTPS sources on the device's web page.
  • The web page shows a summary of each installed application, taken from its manifest: the servers it connects to, the polling interval, what it stores, and whether it starts with the device.
  • Increase version with every change. The page offers Update when a catalog version differs from the installed version. Catalog includes installed applications, marked Installed or Update. Update all appears in Installed apps when at least two compatible updates are available; Refresh fetches the catalogs again.

Part III. Reference

This part summarizes Perinkpheral OS calls and exports for ABI 3. Signatures are abbreviated. Include sdk/host_api.h; complete types, constants and declarations are in sdk/host/*.h.

sdk/host_api.h is the authoritative contract. If this document and the header disagree, the header is correct.

Perinkpheral OS calls return HOST_ERR_* errors directly. Network failures arrive later in a data handler as HOST_FAILED_* status values; see Failed requests in section 9.

Numeric arguments and return values are int32_t unless stated otherwise. A text argument is a pointer and a length in bytes; the text is UTF-8.

A call that returns no value of its own returns HOST_OK or a negative HOST_ERR_* code.

Commands name the subject then the verb (kv_get, gfx_draw_text); queries name the subject and what is asked (gfx_width, time_now); events Perinkpheral OS calls use app_on_<what happened> (app_on_load, app_on_picked).

ABI 3 compatibility

ABI 3 starts with firmware 0.1.30. Existing names, wasm types, privileges, constants, layouts and meanings remain available in later firmware. A changed signature or meaning requires a new ABI; HOST_SINCE_ stamps only entries added after the ABI 3 floor, 0.1.30. Firmware releases and ABI generations are independent. Missing exports remain optional.

The supported set is {3}. The manifest ABI is retained through loading and checked before execution. The device page uses ABI membership and the firmware minimum together for Install, Update and Update all; /api/status reports supported_abis. The downloaded manifest is authoritative. Catalog publishing copies identity and compatibility metadata from the packaged manifest.

tools/perinkpheral contract snapshot records the contract in sdk/abi/3.txt and package hashes separately in sdk/abi/3/fixtures.txt; contract check verifies both in host tests and CI. Recorded entries cannot change or disappear; additions are allowed. Snapshot writes refuse changes too. Frozen packages in sdk/abi/3/ are test inputs and are never rebuilt by tests: Probe, Hello, Settings with translations, and Hello state (presses = 42 as four little-endian bytes). The ABI 3 floor is 0.1.30, the first firmware of ABI 3.

Binary representation and buffers

The contract uses wasm32 little-endian C layouts and two's complement signed integers. Pointers are unsigned 32-bit memory offsets; zero is NULL. 32-bit integers and pointers have size/alignment 4, 64-bit integers 8, bytes 1. Structs keep C field order and natural alignment with trailing padding. sdk/abi/3.txt records every size, alignment, field type and offset. String-table size, count and offsets are little-endian 16-bit words. Picture dimensions are bytes; bitmap rows are high-bit first and padded to whole bytes.

Input buffers are consumed or copied before an import returns. Perinkpheral OS retains only the exported app_data_buffer and app_strings_buffer storage for the loaded instance; keep that storage valid until unload. Handler data is valid until the handler returns. Lengths and capacities count bytes. Text output has no appended NUL, except fixed host_answer_info_t string fields. Negative lengths/capacities or invalid memory ranges give HOST_ERR_ARGUMENT.

kv_get, answer_value, answer_element, session_get, sys_info, sys_app_title and sys_setting_get fail with HOST_ERR_NO_SPACE without copying when the value does not fit. Capacity zero is valid for an empty value. gfx_fit_text also requires room for its whole fitted result and copies nothing on error. text_fill and time_text instead truncate between UTF-8 characters and return bytes copied; text_fill accepts zero capacity, time_text rejects it. Read/format/measurement errors leave outputs untouched; file_read may have copied a prefix before a storage error. answer_info copies min(capacity, Perinkpheral OS's struct size), accepts zero and leaves later bytes untouched. sys_app_list writes up to capacity ids but returns the total count; capacity zero is allowed.

Install and update are consumed after loading and before the callback, including a missing callback or a trap in app_on_load or the callback. A load failure leaves the notification pending until startup or application-list reload. Updated means another module-and-manifest package id, regardless of version-string ordering.

Only HOST_DATA_LAST makes a streamed answer whole. HOST_DATA_FAILED may follow earlier pieces and invalidates them all. An interrupted answer may end with neither flag. Piece boundaries are unspecified, even inside a UTF-8 character or a document marker. Keep the previous displayed result until LAST.

Rendering keeps the existing rules: combined redraw flags choose CLEAN before NO_BLINK before SOON; QUESTION is independent. When dithering is disabled, gfx_set_color shades 1..7 become paper and 8..15 ink. Icon first/last ink coordinates are inclusive; text end_x is exclusive.

System settings expose only the explicit page-visible keys listed in sdk/host/sys.h, which specifies types, units, inclusive ranges, special values and restart behaviour for each. Unknown and internal keys, including refresh_min_button_ms, return HOST_ERR_NOT_FOUND for get, set and range. The Wi-Fi SSID is read-only here; the password cannot be read or written here (HOST_ERR_ARGUMENT). Network changes use the page or SYS_DO_FORGET_NETWORK.
