1. Overview
1. Обзор

perINKpheral is a desk display: a 4.2" black-and-white e-paper panel with four buttons, built on an ESP32-C6. Information intended for reading at a glance is displayed: time, weather, the next meeting, the state of a home.
perINKpheral - настольный дисплей: чёрно-белая панель E-Ink 4,2" с четырьмя кнопками на базе ESP32-C6. Отображается информация, рассчитанная на чтение с одного взгляда: время, погода, ближайшая встреча, состояние дома.

The firmware is called the <i>host</i>. The menu and the settings are provided by the host. All other screens are provided by <i>applications</i>. Applications are installed from a catalog; the firmware is not reflashed.
Прошивка называется <i>хостом</i>. Меню и настройки предоставляются хостом. Все остальные экраны предоставляются <i>приложениями</i>. Приложения устанавливаются из каталога; прошивка при этом не перезаписывается.

An application consists of a WebAssembly module and a manifest. The module is written in C against a single header, <code>sdk/host_api.h</code>, and is executed by an interpreter (wasm3) inside the host.
Приложение состоит из модуля WebAssembly и манифеста. Модуль пишется на C с одним заголовочным файлом, <code>sdk/host_api.h</code>, и исполняется интерпретатором (wasm3) внутри хоста.

The host's own pages, Settings and About, are built as applications with the same header.
Собственные страницы хоста, Settings и About, собраны как приложения с тем же заголовочным файлом.

Дисплей: 400 x 300 пикселей, 1 бит, оттенки серого дизерингом, частичное обновление примерно за 0,5 с

Input: four buttons; short press, long press, key down and key up events

Фоновая работа: ответы, будильники и события устройства доставляются приложению, когда оно не на экране

Хранение: хранилище «ключ-значение» и файлы, сохраняются при перезагрузке и переустановке

Design system: lists, notices, pickers, cells and a button row, drawn by the host
Дизайн-система: списки, сообщения, выбор значения, ячейки и строка кнопок, отрисовываются хостом

Notifications: shown by the host over any screen
Уведомления: показываются хостом поверх любого экрана

Settings: declared in the manifest, edited on the device's web page
Настройки: объявляются в манифесте, редактируются на веб-странице устройства

Localization: strings per language, loaded by the host; Latin with diacritics, Cyrillic and Greek
Локализация: строки по языкам, загружаются хостом; латиница с диакритикой, кириллица и греческий

Tools: build, check and measure an application; control a device over the network
Инструменты: сборка, проверка и измерение приложения; управление устройством по сети

How an application runs
Как работает приложение

An application is a set of exported handlers with fixed names. A handler is called by the host when an event occurs: a button press, a timer, incoming data, a request to draw.
Приложение - это набор экспортируемых обработчиков с фиксированными именами. Обработчик вызывается хостом при наступлении события: нажатие кнопки, таймер, поступление данных, запрос на отрисовку.

The application's state is updated in a handler, and a redraw is requested. <code>app_on_draw()</code> is called by the host when a frame is needed. Refresh timing and method are decided by the host.
Состояние приложения изменяется в обработчике, после чего запрашивается перерисовка. <code>app_on_draw()</code> вызывается хостом, когда нужен кадр. Момент и способ обновления экрана определяются хостом.

One application is loaded at a time. An application is unloaded when it leaves the screen. Persistent state is kept in the application's store; global variables are kept until the unload.
Одновременно загружено одно приложение. Приложение выгружается, когда уходит с экрана. Постоянное состояние хранится в хранилище приложения; глобальные переменные сохраняются до выгрузки.

Handler guarantees
Гарантии для обработчиков

Handlers are run one at a time, each to completion. Locking is unnecessary.
Обработчики выполняются по одному, каждый до завершения. Блокировки не нужны.

A handler is limited to 3 seconds. A handler that exceeds the limit, or traps (for example, on an invalid pointer), is stopped. The application is then terminated and an error screen is shown. The host is unaffected.
Обработчик ограничен 3 секундами. Обработчик, превысивший лимит или вызвавший ловушку (например, на неверном указателе), останавливается. Приложение завершается, показывается экран ошибки. Хост продолжает работу.

Handlers return <code>void</code>. A redraw, the screen or an exit is obtained with a request. Requests are applied after the handler returns.
Обработчики возвращают <code>void</code>. Перерисовка, экран или выход получаются запросом. Запросы применяются после возврата из обработчика.

<code>app_init()</code> is called before any other handler of an instance.
<code>app_init()</code> вызывается раньше любого другого обработчика экземпляра.

Button events are delivered in order, without loss. Pending timers with the same number are merged. The pieces of one answer are delivered in order, in consecutive calls.
События кнопок доставляются по порядку, без потерь. Ожидающие таймеры с одним номером объединяются. Фрагменты одного ответа доставляются по порядку, последовательными вызовами.

Background delivery of an answer can be interrupted. On a button press the instance is unloaded and the remaining pieces are dropped. Only <code>app_on_terminate()</code> is called. The poll is repeated after one minute.
Фоновая доставка ответа может быть прервана. При нажатии кнопки экземпляр выгружается, оставшиеся фрагменты отбрасываются. Вызывается только <code>app_on_terminate()</code>. Опрос повторяется через минуту.

State
Состояние

Global variables are kept until the application is unloaded. Unloading occurs every time the application leaves the screen and after every background call.
Глобальные переменные сохраняются до выгрузки приложения. Выгрузка происходит при каждом уходе приложения с экрана и после каждого фонового вызова.

State is loaded in <code>app_init()</code> and saved in <code>app_on_terminate()</code>, the last call of every instance. A value that must survive a power loss is saved immediately after it changes.
Состояние загружается в <code>app_init()</code> и сохраняется в <code>app_on_terminate()</code> - последнем вызове каждого экземпляра. Значение, которое должно пережить отключение питания, сохраняется сразу после изменения.

Timestamps that stay valid across restarts: <code>time_now()</code>, or <code>time_uptime_ms()</code> together with <code>time_boot_id()</code>. The boot id changes after every restart.
Метки времени, действительные после перезагрузки: <code>time_now()</code> либо <code>time_uptime_ms()</code> вместе с <code>time_boot_id()</code>. Идентификатор загрузки меняется после каждой перезагрузки.

Navigation and refresh
Навигация и обновление экрана

Navigation is organized as a stack. The menu is at the bottom. An application opened from the menu is placed on top. A notification, a host question or an application that requested the screen is placed above the current screen.
Навигация организована как стек. Внизу находится меню. Приложение, открытое из меню, помещается сверху. Уведомление, вопрос хоста или приложение, запросившее экран, помещается над текущим экраном.

The top entry is removed by a short press of BACK. The stack is cleared and the menu is opened by a long press of BACK.
Верхний элемент снимается коротким нажатием BACK. Длинным нажатием BACK стек очищается и открывается меню.

Only the top entry is loaded. An application lower in the stack is unloaded; its state is restored when it returns to the top.

A complete frame is always shown. Refresh timing is decided by the host.
На панели всегда показан целый кадр. Момент обновления определяется хостом.

<code>{{key}}</code> of any setting is replaced by the stored value, percent-encoded: every character except letters, digits and <code>- . _ ~</code> becomes <code>%XX</code>, <b>including <code>/</code></b>. A poll with an empty setting in its URL or headers fails with <code>HOST_FAILED_NOT_READY</code>; a token in a header is therefore required
<code>{{key}}</code> любой настройки заменяется сохранённым значением в URL-кодировании: каждый символ, кроме букв, цифр и <code>- . _ ~</code>, превращается в <code>%XX</code>, <b>включая <code>/</code></b>. Опрос с пустой настройкой в URL или заголовках завершается ошибкой <code>HOST_FAILED_NOT_READY</code>; поэтому токен в заголовке обязателен

Surface and colour

The origin is the top left corner of the surface. <code>gfx_width()</code> and <code>gfx_height()</code> return its size. Use these values for layout.
Начало координат - левый верхний угол поверхности. <code>gfx_width()</code> и <code>gfx_height()</code> возвращают её размер. Используйте эти значения для компоновки.

Drawing calls work inside <code>app_on_draw()</code>. The surface is white at the start of each call. In any other handler, <code>gfx_*</code> and <code>ui_*</code> calls return <code>HOST_ERR_NOT_DRAWING</code>. Drawing is clipped to the surface.

<code>gfx_color()</code> sets the colour for the following calls, from <code>HOST_PAPER</code> (0) to <code>HOST_INK</code> (16). Use greys for filled areas only: thin lines and small text become unreadable.
<code>gfx_color()</code> задаёт цвет для последующих вызовов, от <code>HOST_PAPER</code> (0) до <code>HOST_INK</code> (16). В начале каждого <code>app_on_draw()</code> цвет равен <code>HOST_INK</code>. Промежуточные значения - оттенки серого, получаемые дизерингом. 7. Buttons
7. Кнопки

The buttons are, in order: UP, OK, DOWN, BACK. The host uses them the same way on every screen. Applications should keep these meanings.
Кнопки по порядку: UP, OK, DOWN, BACK. Хост использует их одинаково на всех экранах. Приложениям следует сохранять эти значения.

Each press produces two kinds of events. The raw events are <code>KEYDOWN</code> and <code>KEYUP</code>. The interpreted events are <code>PRESSED</code>, sent when a short press ends, and <code>LONG_PRESSED</code>, sent after 600 ms while the button is still held. Most applications handle only <code>PRESSED</code> and <code>LONG_PRESSED</code>.
Большинство приложений обрабатывает только <code>PRESSED</code> и <code>LONG_PRESSED</code>.

After <code>notify()</code> returns, the host manages the notification. It shows the notice under the header, keeps it until the user presses OK or BACK, and then restores the previous screen.
После возврата из <code>notify()</code> уведомлением управляет хост. Он показывает сообщение под заголовком, держит его, пока пользователь не нажмёт OK или BACK, а затем восстанавливает предыдущий экран.

<code>en.json</code> is required. English is compiled into the module and is used when a translation is unavailable. Every other file contains exactly the same keys. The key <code>manifest</code> is allowed in translations only (see below).
<code>en.json</code> обязателен. Английский встраивается в модуль и используется, когда перевода нет. Все остальные файлы содержат точно те же ключи. Ключ <code>manifest</code> допускается только в переводах (см. ниже).

When the host loads the application, it copies the string table of the device's language into the application's memory, over the English table. <code>app_string()</code> then returns the translated text with no extra call.
При загрузке приложения хост копирует таблицу строк на языке устройства в память приложения поверх английской. После этого <code>app_string()</code> возвращает переведённый текст без дополнительного вызова.

<code>text_fill()</code> replaces <code>{0}</code>, <code>{1}</code> in a string with numbers or texts. A translation can place them in any order. Write each string in one form for all numbers, for example "min".
<code>text_fill()</code> заменяет <code>{0}</code>, <code>{1}</code> в строке числами или текстами. Перевод может располагать их в любом порядке. Пишите каждую строку в одной форме для всех чисел, например "min".

The <code>manifest</code> key of a translation contains the translated parts of the manifest: the title, the title and help of each setting, and labels for the options of a choice. The stored option value does not change; only its label is translated.
Ключ <code>manifest</code> перевода содержит переводимые части манифеста: название, заголовок и пояснение каждой настройки, подписи вариантов выбора. Хранимое значение варианта не меняется; переводится только его подпись.

The build fails if a language is not listed in <code>sdk/languages.json</code> (27 languages, two-letter codes), if a translation has a missing or an extra key, or if a string contains a character that the glyph packs of the language do not cover.
Сборка завершается ошибкой, если языка нет в <code>sdk/languages.json</code> (27 языков, двухбуквенные коды), если в переводе не хватает ключа или есть лишний, либо если строка содержит символ, которого нет в пакетах глифов языка.

Translations are usually about a third longer than English. The kit shortens text that does not fit with "...". Check the translated screens on the device.
Переводы обычно примерно на треть длиннее английского текста. Kit сокращает текст, который не помещается, с "...". Проверяйте переведённые экраны на устройстве.

13. Design rules
13. Правила проектирования

These rules apply to all applications. The host's own screens follow them. Most are conventions; the host checks only a few.
Эти правила относятся ко всем приложениям. Экраны самого хоста им следуют. Большинство из них - соглашения; хост проверяет лишь некоторые.

The device is read from about a metre, in about a second. Choose the main value, draw it largest, and keep everything else small.
Устройство читают примерно с метра, примерно за секунду. Выберите главное значение, нарисуйте его самым крупным, остальное оставьте мелким.

Change a screen only when its data changes. A bar shows a quantity. To indicate work in progress, show a notice with <code>is_working</code>.
Меняйте экран, только когда меняются его данные. Полоса показывает количество. Для индикации работы показывайте сообщение с <code>is_working</code>.

A timer should request a redraw only if the picture will differ. A clock redraws once a minute, on the minute. By default the host allows one refresh per minute that was not caused by a button press. Design for this rate.
Таймер должен запрашивать перерисовку, только если изображение изменится. Часы перерисовываются раз в минуту, на границе минуты. По умолчанию хост допускает одно обновление в минуту без нажатия кнопки. Проектируйте под эту частоту.

Use ink on paper. Use grey for filled areas only. Use white text on a black bar only for the selected item or for new information.
Используйте чернила на бумаге. Серый используйте только для заливок. Белый текст на чёрной полосе используйте только для выбранного элемента или новой информации.

Use common words: "Save", "Remove", "Not set up". If a label needs an explanation, change the label.
Используйте общепринятые слова: "Save", "Remove", "Not set up". Если подпись требует пояснения, смените подпись.

Each byte of executed code uses about four bytes of the interpreter's 64 KB. Each byte of data uses one byte of the 64 KB page, which is mostly free. Prefer a table to a chain of <code>if</code> statements, the kit to custom drawing, <code>pick</code> to a custom parser, and <code>time_text()</code> to custom date formatting.
Каждый байт исполненного кода занимает около четырёх байт из 64 КБ интерпретатора. Каждый байт данных занимает один байт страницы 64 КБ, которая в основном свободна. Предпочитайте таблицу цепочке операторов <code>if</code>, Kit - собственной отрисовке, <code>pick</code> - собственному разборщику, <code>time_text()</code> - собственному форматированию дат.

Mark a small helper that is called from many places with <code>__attribute__((noinline))</code> and compare the build reports.
Небольшую вспомогательную функцию, вызываемую из многих мест, помечайте <code>__attribute__((noinline))</code> и сравнивайте отчёты сборки.

Put pictures in <code>pictures/</code>. Put large pictures in <code>files/</code>.
Размещайте картинки в <code>pictures/</code>. Большие картинки размещайте в <code>files/</code>.

Process an answer as it arrives and keep only the data to display. Allocate working buffers with <code>app_alloc()</code> and release them with a mark.
Обрабатывайте ответ по мере поступления и сохраняйте только данные для отображения. Выделяйте рабочие буферы через <code>app_alloc()</code> и освобождайте их по отметке.

All state that matters must be in the store when <code>app_on_terminate()</code> returns. To test: open the application, leave it, open it again. The screen must look the same.
Всё значимое состояние должно быть в хранилище к моменту возврата из <code>app_on_terminate()</code>. Проверка: откройте приложение, выйдите, откройте снова. Экран должен выглядеть так же.

After a failed or interrupted request, keep the previous data on the screen.
После неудавшегося или прерванного запроса оставляйте на экране прежние данные.

Call <code>ui_reason()</code> to show "Not set up", "No network" or "Loading".
Вызывайте <code>ui_reason()</code>, чтобы показать "Not set up", "No network" или "Loading".

Handle <code>time_now() == 0</code>. Use <code>alarm_set()</code> for a delay ("in ten minutes") and <code>alarm_set_at()</code> for a clock time ("at seven").
Обрабатывайте <code>time_now() == 0</code>. Используйте <code>alarm_set()</code> для задержки («через десять минут») и <code>alarm_set_at()</code> для времени по часам («в семь»).

Declare text such as a token, an address or a city as a manifest setting; the user enters it on the device's web page. On the device, let the user choose from a few values with UP and DOWN.
Текст - токен, адрес, город - объявляйте настройкой в манифесте; пользователь вводит его на веб-странице устройства. На устройстве давайте пользователю выбор из нескольких значений кнопками UP и DOWN.

Use a notification only for events the user asked to be told about, such as a timer or a meeting. Let other information wait until the user looks.
Используйте уведомление только для событий, о которых пользователь просил сообщать, например таймер или встреча. Остальная информация ждёт, пока пользователь посмотрит на устройство.

List only the hosts the application needs. Use a <code>url</code> setting for the user's own server. Use a <code>secret</code> setting for a token and send it through a header placeholder.
Перечисляйте только те адреса, которые нужны приложению. Для собственного сервера пользователя используйте настройку типа <code>url</code>. Для токена используйте настройку типа <code>secret</code> и передавайте его подстановкой в заголовке.

Offer the interval as a setting with a reasonable default. On battery power the host limits every poll to one per five minutes.
Предлагайте интервал как настройку с разумным значением по умолчанию. При питании от батареи хост ограничивает каждый опрос одним разом в пять минут.

The index lists the name, title, version and icon of each application, and its files with their sizes and SHA-256 hashes. The device accepts a file only if both the size and the hash match.
В индексе перечислены имя, название, версия и иконка каждого приложения, а также его файлы с размерами и хешами SHA-256. Устройство принимает файл, только если совпадают и размер, и хеш.

Trust model: HTTPS to a source that the user selected, plus the sandbox. Packages are unsigned.
Модель доверия: HTTPS до источника, выбранного пользователем, плюс песочница. Пакеты не подписываются.

The official catalog is the <code>perinkpheral-apps</code> repository. It is the first source on every device. The user can add up to three more sources on the device's web page by entering a repository address.
Официальный каталог - репозиторий <code>perinkpheral-apps</code>. Это первый источник на каждом устройстве. Пользователь может добавить ещё до трёх источников на веб-странице устройства, указав адрес репозитория.

The web page shows a summary of each installed application, taken from its manifest: the servers it connects to, the polling interval, what it stores, and whether it starts with the device.
Веб-страница показывает сводку по каждому установленному приложению, взятую из манифеста: серверы, к которым оно подключается, интервал опроса, что оно хранит и запускается ли вместе с устройством.

Increase <code>version</code> with every change. The device compares versions to detect updates.
Увеличивайте <code>version</code> при каждом изменении. Устройство сравнивает версии, чтобы обнаружить обновления.
