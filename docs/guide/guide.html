Contents

Part I. Datasheet

1. Overview

perINKpheral is a desk display: a 4.2" black-and-white e-paper panel with four buttons, built on an ESP32-C6. Information intended for reading at a glance is displayed: time, weather, the next meeting, the state of a home.

The firmware is called the host. The menu and the settings are provided by the host. All other screens are provided by applications. Applications are installed from a catalog; the firmware is not reflashed.

An application consists of a WebAssembly module and a manifest. The module is written in C against a single header, sdk/host_api.h, and is executed by an interpreter (wasm3) inside the host.

The host's own pages, Settings and About, are built as applications with the same header.

Features

  • Display: 400 x 300 pixels, 1 bit, dithered greys, partial refresh in about 0.5 s
  • Input: four buttons; short press, long press, key down and key up events
  • Sandbox: 64 KB of private memory; network access through the host only
  • Network: HTTP and HTTPS requests performed by the host, as scheduled polls or on request from the code
  • Data: the host extracts values from JSON answers; any answer can be streamed in 1 KB pieces
  • Background work: answers, alarms and device events are delivered while the application is off the screen
  • Storage: a key-value store and files, kept across restarts and reinstalls
  • Design system: lists, notices, pickers, cells and a button row, drawn by the host
  • Notifications: shown by the host over any screen
  • Settings: declared in the manifest, edited on the device's web page
  • Localization: strings per language, loaded by the host; Latin with diacritics, Cyrillic and Greek
  • Tools: build, check and measure an application; control a device over the network

How an application runs

An application is a set of exported handlers with fixed names. A handler is called by the host when an event occurs: a button press, a timer, incoming data, a request to draw.

The application's state is updated in a handler, and a redraw is requested. app_on_draw() is called by the host when a frame is needed. Refresh timing and method are decided by the host.

One application is loaded at a time. An application is unloaded when it leaves the screen. Persistent state is kept in the application's store; global variables are kept until the unload.

3. Execution model

An application is loaded for a handler call and can be unloaded after it.

Application lifecycle

EventInstanceHandlers, in order
The user opens the applicationLoaded; stays while it has the screenapp_init, app_on_focus, app_on_draw ... app_on_blur, app_on_terminate
An answer, alarm, intent or settings change while on the screenSame instanceapp_on_data / app_on_values / app_on_alarm / app_on_intent / app_on_settings
The same while off the screenLoaded for the call, unloaded after it. The current screen is suspended and restoredapp_init, the handler, app_on_terminate
request_focus() granted by the hostStays, on top of the stack... app_on_focus, app_on_draw
The application leaves the screen: BACK, the menu, another application on topUnloadedapp_on_blur, app_on_terminate

Handler guarantees

  • Handlers are run one at a time, each to completion. Locking is unnecessary.
  • A handler is limited to 3 seconds. A handler that exceeds the limit, or traps (for example, on an invalid pointer), is stopped. The application is then terminated and an error screen is shown. The host is unaffected.
  • Handlers return void. A redraw, the screen or an exit is obtained with a request. Requests are applied after the handler returns.
  • app_init() is called before any other handler of an instance.
  • Button events are delivered in order, without loss. Pending timers with the same number are merged. The pieces of one answer are delivered in order, in consecutive calls.
  • Background delivery of an answer can be interrupted. On a button press the instance is unloaded and the remaining pieces are dropped. Only app_on_terminate() is called. The poll is repeated after one minute.

State

Global variables are kept until the application is unloaded. Unloading occurs every time the application leaves the screen and after every background call.

State is loaded in app_init() and saved in app_on_terminate(), the last call of every instance. A value that must survive a power loss is saved immediately after it changes.

Timestamps that stay valid across restarts: time_now(), or time_uptime_ms() together with time_boot_id(). The boot id changes after every restart.

Navigation and refresh

Navigation is organized as a stack. The menu is at the bottom. An application opened from the menu is placed on top. A notification, a host question or an application that requested the screen is placed above the current screen.

The top entry is removed by a short press of BACK. The stack is cleared and the menu is opened by a long press of BACK.

Only the top entry is loaded. An application lower in the stack is unloaded; its state is restored when it returns to the top.

The panel is controlled by the host. Each new frame is compared with the frame on the panel, and only the changed area is sent. A refresh without a button press is postponed if the previous one was too recent.

A complete frame is always shown. Refresh timing is decided by the host.

Part II. Development guide

4. A first application

Requirements

  • wasi-sdk 34 or newer. It provides clang for the wasm32 target. Set WASI_SDK_PATH to its location.
  • Python 3. The tools use the standard library only.
  • A checkout of the perinkpheral repository. It contains sdk/ and tools/.
  • A device on the same network, running a firmware with the development tools enabled (the default). The device shows its address on the second page of About. Set PERINKPHERAL_HOST to this address.

Create, build, run

tools/devtool/devtool.py new my-app --title "My app"     # create a folder from the SDK sample
tools/devtool/devtool.py run my-app                      # build, upload, restart into the application
tools/devtool/devtool.py serve my-app                    # local page: live screen, buttons, log, Run

run builds the application, uploads it and restarts the device into it. This takes about ten seconds. The firmware is not reflashed.

The build treats compiler warnings as errors (-Wall -Wextra -Werror). An unused parameter is marked with (void)name;.

serve starts a local web page with the live screen, the four buttons, the device log and a Run button. The arrow keys, Enter and Backspace act as the buttons.

new also creates a CMakeLists.txt in the application's folder. Open this folder in an IDE that supports CMake, such as CLion or VS Code.

The IDE resolves the SDK headers and the generated strings.h and pictures.h. The project has three build targets: my-app (build), my-app-run (build and run on the device) and my-app-serve (the live page).

Set WASI_SDK_PATH and PERINKPHERAL_HOST in the CMake environment of the IDE.

Sample application

#include "app_text.h"
#include "host_api.h"

#define MARGIN 16

static const char PRESSES_KEY[] = "presses";
#define PRESSES_KEY_LENGTH ((int32_t)sizeof PRESSES_KEY - 1)

static int32_t presses;

static void draw_line(int32_t line, const char *text)
{
    int32_t line_height = gfx_font_height(HOST_FONT_TEXT);
    gfx_text(MARGIN, MARGIN + line * line_height, HOST_FONT_TEXT, text, app_text_length(text));
}

void app_init(void)                 /* load the state from the store */
{
    kv_get(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_terminate(void)         /* save the state before the unload */
{
    kv_set(PRESSES_KEY, PRESSES_KEY_LENGTH, &presses, sizeof presses);
}

void app_on_button(int32_t event)   /* update the state, request a redraw */
{
    switch (event) {
    case BTN_UP_PRESSED:
    case BTN_OK_PRESSED:
    case BTN_DOWN_PRESSED:
        presses++;
        request_redraw(HOST_REDRAW_NORMAL);
        break;
    }
}

void app_on_draw(void)              /* draw the whole frame from the state */
{
    char       counter_buffer[32];
    app_text_t counter;
    app_text_start(&counter, counter_buffer, sizeof counter_buffer);
    app_text_add(&counter, "Presses: ");
    app_text_add_number(&counter, presses);

    draw_line(0, "Hello from wasm");
    draw_line(2, counter_buffer);
}

BACK is handled by the host here: a short press of BACK closes an application that has no app_on_back() export.

Settings

Settings are declared in the manifest. The device's web page builds the settings form from the manifest alone. Each value is stored as text in the application's store, under the key of the setting.

The application reads a setting with kv_get() and the key of the setting.

When the user saves the form, the host calls app_on_settings() and repeats all polls immediately.

  • url and link settings are read-only for the application: kv_set() on their keys fails. When the user changes such a setting, the host erases the secrets that were not entered again, so a token stays with the server it was entered for.
  • title is 1 to 31 characters. help is up to 95 characters.

6. Screen

Surface and colour

  • The origin is the top left corner of the surface. gfx_width() and gfx_height() return its size. Use these values for layout.
  • Drawing calls work inside app_on_draw(). The surface is white at the start of each call. In any other handler, gfx_* and ui_* calls return HOST_ERR_NOT_DRAWING. Drawing is clipped to the surface.
  • gfx_color() sets the colour for the following calls, from HOST_PAPER (0) to HOST_INK (16). The colour is HOST_INK at the start of each app_on_draw(). Intermediate values are dithered greys. Use greys for filled areas only: thin lines and small text become unreadable.
  • The standard margin is HOST_UI_MARGIN (16 px). Use it at the left and right edges.

Fonts

A font constant selects a size. The typeface is a user setting: Departure Mono (monospaced) or Jersey (proportional). Character widths differ between the two, so layout is based on measured widths.

Measure text with gfx_text_width(), gfx_font_height(), gfx_font_ascent() and gfx_font_cap_height().

  • The y argument of gfx_text() is the top of the line. The baseline is at y + ascent; the top of the capitals is at y + ascent - cap_height.
  • Add HOST_FONT_TABULAR to the font for numbers that change in place, such as a clock or a countdown. All digits then have the same width. Every call that takes a font accepts the flag. Pass the same flag when measuring.
  • gfx_text_fit() shortens a text to a given width and appends "...". It cuts between characters, so the result is valid UTF-8.

Text beyond ASCII

All text is UTF-8. The host draws each character using the first available option:

  1. The glyph of the character. Printable ASCII is always available. Latin letters with diacritics, Cyrillic and Greek are available when the user has installed the glyph pack (Settings, Language, on the device's web page).
  2. An ASCII transliteration: "Moskva", "Strasse", "Athina". Typographic dashes and quotes become plain ones.
  3. A question mark.

The degree sign is built in at every size.

The width of a text depends on which option was used. Always measure a text before placing it.

Limits on user-visible text, such as a title or an option, are given in characters. A field holds half as many two-byte characters as one-byte characters.

Rules for text files:

  • A line of the form name: starts a picture.
  • Rows before the first such line form a picture named after the file.
  • All rows of a picture have the same length.
  • A picture is at most 255 cells wide and 255 cells high.

The constant is PICTURE_ followed by the picture name in upper case. Characters other than letters and digits are replaced with _. Example: half-moon becomes PICTURE_HALF_MOON.

mkpicture.py --show prints the pictures as the tool read them.

A picture is stored as one bit per cell. gfx_picture() draws it with a cell size of 1 to 16 pixels, so one picture can be used at several sizes.

Use the same grids as the built-in icons: 11 cells, or 22 and 44 cells for more detail. Pictures then match the icons in weight.

Place a picture that is too large for the module in files/ and draw it with gfx_bitmap_file(). The host reads the file directly; the picture does not use the application's memory.

Kit

The kit is the set of interface parts that the host's own screens are built from. Applications can use the same parts through the ui_* calls.

Using the kit is optional: gfx_* calls can draw anything. The kit has three advantages. The application looks like the rest of the system. It follows future changes of the look without a rebuild. It is smaller, because the drawing code is in the host.

7. Buttons

The buttons are, in order: UP, OK, DOWN, BACK. The host uses them the same way on every screen. Applications should keep these meanings.

Each press produces two kinds of events. The raw events are KEYDOWN and KEYUP. The interpreted events are PRESSED, sent when a short press ends, and LONG_PRESSED, sent after 600 ms while the button is still held. A long press does not produce PRESSED.

Most applications handle only PRESSED and LONG_PRESSED.

The event value combines the button and the action. Each combination has a constant:

void app_on_button(int32_t event)
{
    switch (event) {
    case BTN_OK_PRESSED:       start();  break;
    case BTN_OK_LONG_PRESSED:  reset();  break;
    }
    request_redraw(HOST_REDRAW_NORMAL);
}

BACK

ApplicationShort press of BACK
Without app_on_back()Closes the application (one step down the stack)
With app_on_back()Delivered to app_on_back(). Typical handling: go one page back; on the first page call request_exit()

A short press of BACK goes to app_on_back(), or closes the application if it has no such export. A long press of BACK opens the host's menu. app_on_button() receives all other events.

request_exit() removes the application from the top of the stack. The user returns to the previous screen. This also applies to an application that took the screen with request_focus().

Lists, pickers, dates

#include "app_ui.h"

static app_list_t list = { .count = 12 };          /* .selected = -1: no selection, rows scroll */

void app_on_button(int32_t event)
{
    switch (app_list_button(&list, event)) {
    case APP_UI_DONE:      open_item(list.selected);               break;   /* OK */
    case APP_UI_CHANGED:   request_redraw(HOST_REDRAW_NO_BLINK);   break;   /* UP, DOWN */
    default:               break;
    }
}

void app_on_draw(void)
{
    int32_t first = app_list_first(&list);
    for (int32_t row = first; row < first + ui_list_visible(&list) && row < list.count; row++) {
        ui_list_row(&list, row, label_of(row), label_length(row), "", 0, HOST_ICON_NONE);
    }
}

app_picker_t and app_date_t follow the same pattern. The application keeps a struct, passes button events to one function and draws with another. The button function returns changed, done, cancelled or ignored.

8. Storage

Store

kv_get() and kv_set() read and write small values by key. Each application has a private namespace.

The store holds the application's state and its settings. The data is kept when the application is removed and is available again after a reinstall.

typedef struct { int32_t version; int32_t minutes; int64_t ends_at; } state_t;
static state_t state;

void app_init(void)
{
    if (kv_get("state", 5, &state, sizeof state) != sizeof state || state.version != 2) {
        state = (state_t){ .version = 2, .minutes = 25 };     /* no stored state, or an older version */
    }
}
  • Put a version field in every stored struct and check it on load. A newer version of the application will read data written by an older one.
  • Every write wears the flash memory. Write only when the data has changed. Do not write on every timer tick.
  • kv_set() with a length of 0 deletes the key.

Files

Use files for data that does not fit in a store value: a downloaded list, a cache, a picture.

file_read() and file_write() take an offset. A file can be read and extended in parts, so it never has to be held in memory in full.

The files from the files/ folder of the package are installed with the application.

9. Network

All network access goes through the host. The application describes a request; the host performs it and delivers the answer. The host performs one request at a time for the whole device. Delivery is independent of whether the application is on the screen.

Network availability is reported in the answer: a request made without a network fails with HOST_FAILED_NO_NETWORK.

MethodTriggerDelivery
Poll with pickScheduleapp_on_values(), once, with the extracted values
Poll without pickScheduleapp_on_data() in pieces, with the poll number
http_request()Code: after a button press, or as a follow-up requestapp_on_data() in pieces, with the tag chosen by the application (16 - 255)

Values extracted by the host

#include "app_values.h"
enum { VALUE_TEMPERATURE, VALUE_CODE };            /* order of "pick" in the manifest */

void app_on_values(int32_t request, int32_t http_status)
{
    int32_t tenths, code;
    last_status = http_status;                     /* for ui_reason() when there is no data */
    if (http_status == 200 &&
        app_value_number(VALUE_TEMPERATURE, 1, &tenths) &&      /* "21.46" -> 215 */
        app_value_number(VALUE_CODE, 0, &code)) {
        keep(tenths, code);                        /* save to the store */
    }                                              /* otherwise keep the previous data */
    request_redraw(HOST_REDRAW_NORMAL);
}

Numbers are integers. app_value_number() returns the value scaled by the requested number of decimals, rounded.

A path that is absent from the answer has no value: app_value_number() returns false. An absent value means no data.

Streamed answers

void app_on_data(int32_t request, const uint8_t *data, int32_t length, int32_t flags, int32_t http_status)
{
    if (flags & HOST_DATA_FAILED) {                /* single call, no data: http_status is a HOST_FAILED_* code */
        last_status = http_status;
        return;
    }
    if (flags & HOST_DATA_FIRST) {                 /* the first piece carries the HTTP status */
        last_status = http_status;
        begin_reading();                           /* reset the parser */
    }
    read_piece(data, length);                      /* data is valid until the handler returns */
    if (flags & HOST_DATA_LAST) {
        take_what_was_read();                      /* the answer is complete */
        request_redraw(HOST_REDRAW_NORMAL);
    }
}
  • Process each piece when it arrives and keep only the data to display. Use a state machine, the SDK's json_pick or a custom parser. An answer can be several megabytes; the application has 64 KB.
  • Replace the displayed data only on HOST_DATA_LAST. Delivery can stop without a last piece and without a failure (section 3). HOST_DATA_FIRST always starts a new answer.
  • Inside the handler, data_response() returns the response metadata: status, Content-Length, Content-Type, ETag, Last-Modified, Location, Link and Retry-After.

Requests from code

enum { REQUEST_TOGGLE = HOST_REQUEST_FIRST };
static const char URL[]     = "{{server}}/api/services/light/toggle";
static const char HEADERS[] = "Authorization: Bearer {{token}}\nContent-Type: application/json";

http_request(REQUEST_TOGGLE, HOST_HTTP_POST, URL, sizeof URL - 1, HEADERS, sizeof HEADERS - 1,
             body, body_length);
  • Requests are allowed only to the hosts listed in the manifest. {{key}} placeholders work in the URL and in header values, so the code does not need to read the token.
  • HOST_ERR_NO_SPACE means that the request queue of the device is full (two waiting requests). Retry later.
  • The host follows up to three redirects for a GET. A redirect to a host outside the list fails with HOST_FAILED_NOT_ALLOWED. A request with a body is sent once; its redirect response is delivered as the answer.
  • poll_now(n) runs poll n immediately, for example when the user presses a refresh button. poll_set_interval(n, seconds) changes the interval of a poll from code, for example to honour a Retry-After header.

11. Time

  • time_now() returns Unix time in seconds. It returns 0 until the device has obtained the time. The application must handle this case.
  • Display local time. The host owns the time zone. time_local() returns the current local date and time, time_local_at() converts any moment, and time_from_local() converts a local date and time back to Unix time, for example for alarm_set_at().
  • time_text() formats a moment as text in the device's language. Applications do not need their own names of days and months. Formats: "15:04", "Fri 13 Nov", "Friday", "13 November", and a relative form: "15:04", "Tmrw 15:04", "Sat 15:04", "21 Nov".
  • To be called when the clock is set or changed, declare the time_changed intent.

12. Languages

An application displays its text in the language of the device. The developer provides the translations. The host loads the translation for the current language.

strings/en.json    { "no_events": "No events", "starts_in": "In {0} min" }
strings/ru.json    { "no_events": "Нет событий", "starts_in": "Через {0} мин",
                     "manifest": { "title": "Календарь",
                                   "settings": { "every": { "title": "Обновление",
                                                            "options": { "15 min": "15 мин" } } } } }
#include "strings.h"                              /* generated by mkapp: STR_NO_EVENTS, STR_STARTS_IN, app_string() */

const char *text = app_string(STR_NO_EVENTS);     /* text in the device's language */

const host_text_argument_t minutes = { .number = 10 };
char line[32];
int32_t length = text_fill(app_string(STR_STARTS_IN), app_text_length(app_string(STR_STARTS_IN)),
                           &minutes, 1, line, sizeof line);          /* "In 10 min" */
  • en.json is required. English is compiled into the module and is used when a translation is unavailable. Every other file contains exactly the same keys. The key manifest is allowed in translations only (see below).
  • When the host loads the application, it copies the string table of the device's language into the application's memory, over the English table. app_string() then returns the translated text with no extra call.
  • text_fill() replaces {0}, {1} in a string with numbers or texts. A translation can place them in any order. Write each string in one form for all numbers, for example "min".
  • The manifest key of a translation contains the translated parts of the manifest: the title, the title and help of each setting, and labels for the options of a choice. The stored option value does not change; only its label is translated.
  • The build fails if a language is not listed in sdk/languages.json (27 languages, two-letter codes), if a translation has a missing or an extra key, or if a string contains a character that the glyph packs of the language do not cover.
  • Translations are usually about a third longer than English. The kit shortens text that does not fit with "...". Check the translated screens on the device.

13. Design rules

These rules apply to all applications. The host's own screens follow them. Most are conventions; the host checks only a few.

Screen content

Show one main value per screen. The device is read from about a metre, in about a second. Choose the main value, draw it largest, and keep everything else small.
Keep screens static. Change a screen only when its data changes. A bar shows a quantity. To indicate work in progress, show a notice with is_working.
Redraw only when the content changes. A timer should request a redraw only if the picture will differ. A clock redraws once a minute, on the minute. By default the host allows one refresh per minute that was not caused by a button press. Design for this rate.
Draw black on white. Use ink on paper. Use grey for filled areas only. Use white text on a black bar only for the selected item or for new information.
Keep interface text short and standard. Use common words: "Save", "Remove", "Not set up". If a label needs an explanation, change the label.

Memory

Minimize code size before data size. Each byte of executed code uses about four bytes of the interpreter's 64 KB. Each byte of data uses one byte of the 64 KB page, which is mostly free. Prefer a table to a chain of if statements, the kit to custom drawing, pick to a custom parser, and time_text() to custom date formatting.
Keep shared helpers out of line. Mark a small helper that is called from many places with __attribute__((noinline)) and compare the build reports.
Store pictures as bits. Put pictures in pictures/. Put large pictures in files/.
Process answers as a stream. Process an answer as it arrives and keep only the data to display. Allocate working buffers with app_alloc() and release them with a mark.

State and time

Save state before every unload. All state that matters must be in the store when app_on_terminate() returns. To test: open the application, leave it, open it again. The screen must look the same.
Keep the displayed data until new data is complete. After a failed or interrupted request, keep the previous data on the screen.
Explain an empty screen. Call ui_reason() to show "Not set up", "No network" or "Loading".
Handle an unknown or changed clock. Handle time_now() == 0. Use alarm_set() for a delay ("in ten minutes") and alarm_set_at() for a clock time ("at seven").

Interaction and data

Take text input on the web page. Declare text such as a token, an address or a city as a manifest setting; the user enters it on the device's web page. On the device, let the user choose from a few values with UP and DOWN.
Take the screen rarely. Use a notification only for events the user asked to be told about, such as a timer or a meeting. Let other information wait until the user looks.
Send user data only where the user directs. List only the hosts the application needs. Use a url setting for the user's own server. Use a secret setting for a token and send it through a header placeholder.
Poll no more often than the data changes. Offer the interval as a setting with a reasonable default. On battery power the host limits every poll to one per five minutes.

15. Publishing

A device installs applications from catalogs. A catalog is a folder of static files with an index. It can be hosted anywhere that serves HTTPS, for example as raw files of a git repository or as a static site.

tools/catalog/mkcatalog.py my-apps --out catalog       # build all applications in the folder
                                                       # output: catalog/catalog.json, one folder per application
  • The index lists the name, title, version and icon of each application, and its files with their sizes and SHA-256 hashes. The device accepts a file only if both the size and the hash match.
  • Trust model: HTTPS to a source that the user selected, plus the sandbox. Packages are unsigned.
  • The official catalog is the perinkpheral-apps repository. It is the first source on every device. The user can add up to three more sources on the device's web page by entering a repository address.
  • The web page shows a summary of each installed application, taken from its manifest: the servers it connects to, the polling interval, what it stores, and whether it starts with the device.
  • Increase version with every change. The device compares versions to detect updates.

22. System API

The system API is the set of sys_* calls. The host's own pages use it.

Any application can use the system API if its manifest contains "system": true. The web page warns the user before installing such an application. A module that imports a sys_* call without this declaration is rejected.

23. SDK library

mkapp links the library into every application. Unused functions are removed. The headers are in sdk/lib.

bool is the standard type from <stdbool.h>. Text arguments are null-terminated unless stated otherwise.

app_text.h: short strings without printf

typedef struct { char *next; char *last; } app_text_t;      /* declared by the caller */

void    app_text_start(app_text_t *text, char *buffer, int32_t buffer_size);
void    app_text_add(app_text_t *text, const char *more);   /* excess text is dropped at a character boundary */
void    app_text_add_number(app_text_t *text, int32_t value);               /* decimal, "-" when negative */
void    app_text_add_padded(app_text_t *text, int32_t value, int32_t digits);          /* 7, 2 -> "07" */
int32_t app_text_length(const char *text);                  /* length of any null-terminated text */

The buffer is always null-terminated and stays within its size. The text is complete after each call.

app_values.h: what the host picked

bool app_value_text(int32_t index, char *text, int32_t text_size);        /* false: value absent or buffer too small */
bool app_value_number(int32_t index, int32_t decimals, int32_t *number);  /* "-3.46", 1 -> -35; false: value absent */
bool app_parse_number(const char *text, int32_t decimals, int32_t *number);    /* the same for a given text */

These functions work only inside app_on_values(). index is the position of the path in the pick list of the manifest.

#include "strings.h"      /* generated from strings/:  enum { STR_NO_EVENTS, ... };  const char *app_string(int32_t id); */
#include "pictures.h"     /* generated from pictures/: static const uint8_t PICTURE_DROP[] = { width, height, bits }; */

strings.h and pictures.h are generated for each application. The build places them first on the include path, so a system header with the same name is not used.

memcpy, memmove, memset and strlen are provided because the compiler generates calls to them. They are the whole C library of the platform. They are declared in no SDK header: the code that calls one directly declares its prototype. app_text_length() of app_text.h replaces strlen.
